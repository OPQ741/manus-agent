# 02 · 产品需求文档（PRD）

**产品名**：Nucleus Studio（原子核·造物台）
**一句话**：说一句话，得到一个能用的应用；不满意就继续说，随时能退回去。
**版本**：v1.0（笔试交付版）
**日期**：2026-11

---

## 1. 产品目标

| 目标 | 衡量方式 | 目标值 |
| --- | --- | --- |
| 冷启动零摩擦 | 首页 → 第一个应用出现的时间 | ≤ 60s（本地引擎），≤ 120s（云模型） |
| 生成可用 | 生成物在浏览器中无未捕获错误 | ≥ 90% 的生成结果首次预览无 error |
| 过程可见 | 生成过程中界面同时展示「当前阶段」与「当前文件名」 | 100% 的生成会话满足 |
| 迭代有效 | 二轮修改后错误率下降 | 100% 的修复请求至少消除 1 个已捕获错误 |
| 可交付 | 生成物能离开平台 | 100% 项目可导出 ZIP / 生成分享链接 |

**核心体验承诺**：任何一次生成，用户都能看到"它正在做什么"，任何一次失败，用户都能看到"为什么失败、下一步点哪里"。

---

## 2. 角色与权限

只有一种角色：**访客（无需注册）**。

- 所有项目公开可读（Demo 定位：分享即展示）；
- 写操作不做身份隔离，但每个浏览器实例生成 `visitorId` 写入 `created_by`，仅用于 UI 上标出"我创建的"；
- 这是一个明确的权衡，见 03 文档「安全与边界」。

---

## 3. 信息架构

```
/                     首页：Hero 输入框 + 灵感标签 + 我的项目 + 全部项目
/studio/:id           工作台：左对话 / 右预览（代码 / 版本 / 分享）
/p/:slug              只读分享页：直接运行的应用 + 「在 Nucleus 中打开」
/settings             设置：生成引擎（本地 / 云模型）、模型地址与 Key、设计偏好
```

## 4. 功能需求

### 4.1 P0 — 基本使用流程

#### F1 创建应用（首页）

- 大输入框（多行，`⌘/Ctrl + Enter` 提交），placeholder 给示例；
- 「灵感」快捷标签 ≥ 6 个（记账 / 待办 / 番茄钟 / 看板 / 计算器 / 落地页），点击即填入；
- 提交后立即 `POST /api/projects` 建项目 → 跳转 `/studio/:id`，**不阻塞在生成上**；
- 空输入 / 超过 2000 字给出内联提示，不发请求。

#### F2 Agent 生成（工作台主流程）

生成分三段，每段在对话流里可见。三段对应 Atoms 的**任务简报 → 工程师动手 → 负责人验收**：

| 阶段 | 对应 Atoms 环节 | UI 表现 | 数据 |
| --- | --- | --- | --- |
| `plan` | ① 任务简报 | 一张「方案卡」：应用名、一句话简介、技术栈、步骤清单、文件清单 | `Plan` 对象 |
| `write` | ② 过程可见 | 每个文件一行，显示路径 + 行数，内容逐字流式（打字机）；当前写入的文件在代码面板高亮 | 文件 → 内容 |
| `verify` | ② 过程可见（验收） | 一组静态检查项：入口文件存在 / 引用完整性 / 外链资源 / 体积 / 沙箱安全 | `Check[]` |

- 这三段在 UI 上呈现为**活动卡片**（阶段药丸 + 逐文件流 + 检查徽章），信息全部来自真实执行结果，不使用拟态标签；
- 生成过程中「发送」按钮变为「停止（保留已完成文件）」；
  - **语义**：连接不断开，服务端中断引擎后，把**正常闭合**的文件提交为一个新版本（标签「中断保留 · N 个文件有变化」）；写了一半的文件回退到旧版；本轮新开但没写完的文件丢弃；
  - 若没有任何文件写完，**不产生版本**（避免历史里出现空版本）；
  - 客户端通过 `done{partial:true}` 事件收到确认，并刷新预览；
- 生成完成后预览自动刷新，右侧切到「预览」，**"生成完成"与"可以立刻点"同时发生**（③ 环节要求）；
- 错误（网络 / 模型 / 协议）在对话流中显示为可重试的错误卡，**保留已有产物**；同时顶部弹出可操作的错误条（见 F11）。

#### F3 预览（沙箱）

- `iframe sandbox="allow-scripts allow-forms allow-modals allow-popups allow-downloads"` + `srcdoc`；
- 视口切换：桌面（100%）/ 平板（768）/ 手机（390）；
- 刷新按钮、在新窗口打开、复制分享链接；
- **常驻健康度指示灯**：工具栏上常驻显示静态自检结论（`6 项检查通过` / `2 项提醒` / `1 项阻断`），点开可看每一项的判定与详情；`block` 级失败时预览区显示占位与具体原因。

#### F4 对话迭代

- 输入框支持多轮；每轮把「当前文件集合」+「用户指令」构造成上下文；
- Agent 只需返回**变更的文件**（增量写入）；未提及的文件保持不变；
- 每次成功应用变更 → 自动落一个版本快照；
- 对话历史持久化，刷新页面后恢复。

#### F5 代码查看

- 文件树（按目录分组）+ 代码面板；
- 语法高亮（HTML/CSS/JS，自研轻量高亮，零依赖）；
- 复制当前文件、行数统计、等宽字体、暗色底。

### 4.2 P1 — 延展能力

#### F6 版本时间线

- 每个版本记录：序号、触发它的用户指令、变更文件列表、时间；
- 支持「回滚到此版本」（回滚本身也生成一个新版本，不销毁历史）；
- 支持查看某版本的文件级 diff（+ / − 行数，折叠展示）；
- **与 Atoms「还原到该消息之前的状态」的等价性**：每次成功生成恰好产生「一条 Agent 消息 + 一个版本」，二者一一对应。因此"回滚到某条消息之前"≡"回滚到该消息对应版本的上一版"——用户不需要理解版本号，只需要理解"回到刚才那次之前的样子"。

#### F7 运行时自愈

- 预览 iframe 注入错误桥：捕获 `error` / `unhandledrejection` / `console.error`；
- 右上角浮条「检测到 N 个运行时错误 · 让 Agent 修复」；
- 点击后把「错误信息 + 堆栈 + 当前代码」打包成修复指令，走 F4 的迭代链路；
- 错误去重（相同 message 只计一次），上限 20 条，避免刷屏。

#### F8 导出与分享

- 导出：`GET /api/projects/:id/export` → ZIP（含 `index.html`、`styles.css`、`app.js`、`README.md`）；
- 分享：`/p/:slug` 只读页，直接渲染应用，顶部一条轻量工具条（作者标识 / 引擎 / 「在 Studio 中打开」/「导出」）。

#### F9 设置

- 引擎选择：`本地合成`（默认）/ `云模型`（OpenAI 兼容）；
- 云模型配置：Base URL、模型名、API Key；保存后服务端只回显「已配置 + 掩码」；
- 「测试连接」按钮：发一条极短请求，返回延迟与模型名；
- 设计偏好：主色（6 个预设）/ 明暗（浅色、深色、跟随系统）/ 语言（中文/English）——作为提示词参数注入，两条引擎都生效。

#### F10 我的项目

- 首页项目区提供「全部 / 我的」切换；
- 「我的」= 只列出**当前浏览器**创建的项目（`createdBy` 与本地 `visitorId` 匹配），服务端按 `?mine=1` + `x-visitor` 头过滤；
- 自己创建的项目卡片上标「我创建的」；
- 列表默认缓存 30 秒，「刷新」按钮可强制绕过；
- **明确的边界**：这是**展示层过滤**，不是安全边界——项目公开可读、公开可写，免注册是题面要求。

#### F11 错误处置指引

- 服务端返回归一化错误码（`llm_auth` / `llm_quota` / `llm_timeout` / `llm_network` / `protocol_error` / `engine_unconfigured` / `busy` / `not_found` / `bad_request` / `internal`）；
- 界面把每个错误码翻译成三段：**发生了什么**（标题）+ **为什么**（原因）+ **现在点哪里**（一个可点按钮：去设置 / 重新生成 / 回首页）；
- 流式过程中的 `error` 事件必须被接住并展示（不能只依赖 HTTP 抛错），否则模型 401 这类失败会变成"静默失败"。

## 5. 关键交互细节

1. **流式打字机**：文件内容按 chunk 追加，渲染节流到 ~16ms/帧，避免长文件卡顿。
2. **不打断**：生成中允许切换右侧页签（预览 / 代码 / 版本），流不受影响；**切换项目会中止当前生成**（组件卸载 → SSE 断开），但服务端会把已完成的文件提交成「中断保留」版本，数据不丢。
3. **幂等**：同一项目并发两次生成时，后一次直接 409「已有生成进行中」。
4. **失败不脏数据**：生成失败不写版本、不改文件，只在对话流留一条错误。
5. **首屏性能**：首页不发模型请求；项目列表走缓存（TTL 30s，刷新按钮可强制绕过）。
6. **快捷键**：`⌘/Ctrl+Enter` 发送，`⌘/Ctrl+K` 聚焦输入框，`Esc` 停止生成（等同点「停止」，保留已完成文件）。

## 6. 状态与异常矩阵

| 场景 | 表现 | 用户可做什么 |
| --- | --- | --- |
| 云模型未配置 | 生成前拦截，提示「当前为本地引擎」并给出切换入口 | 切本地引擎 / 去设置配置 |
| 模型 401 / 余额不足 | 错误条：「模型拒绝了这个请求」+「Key 填错、已过期或没有权限」+ 按钮「去设置检查 Key」 | 去设置 / 重试 |
| 模型超时（30s 无首字节） | 错误条：「模型响应超时」+「首字节超过 30s 或中途断开」+ 按钮「重新生成」 | 重试 / 切本地引擎 |
| 协议解析失败（模型没按格式输出） | 标记 `parse_warning`，尽力恢复文件；全失败则错误条「模型没有按协议输出」 | 重试 / 换引擎 |
| 用户主动停止 | 已写完的文件保留为新版本（标签「中断保留」），写了一半的回退到旧版 | 继续提需求 / 回滚 |
| 未生成入口文件 | 预览区占位，说明缺什么；健康度指示灯显示「1 项阻断」 | 对话要求「补一个 index.html」 |
| 运行时错误 | 浮条 + 一键修复 | 修复 / 忽略 |
| 项目不存在 | 404 页 + 回首页 | 回首页 |
| 导出失败 | toast | 重试 |

## 7. 非功能需求

| 项 | 要求 |
| --- | --- |
| 首屏 | < 1.5s（本地网络），JS 体积 < 200KB gzip |
| 生成延迟 | 本地引擎首字节 < 300ms，全文 < 1.5s |
| 并发 | 单进程支持 20 并发流式连接（Demo 规模） |
| 数据 | 写操作原子（临时文件 + rename），进程崩溃不产生半个文件 |
| 可访问性 | 所有交互元素可 Tab 聚焦，对比度 ≥ 4.5:1，支持 `prefers-reduced-motion` |
| 兼容 | Chrome / Edge / Safari 最新两个大版本；≥ 1280 宽为桌面布局，< 900 折叠为竖排 |
| 安全 | 生成物在 sandbox iframe 内运行；`/api` 无用户输入拼接到文件系统路径 |

## 8. 验收清单（Definition of Done）

### 8.0 功能验收

- [ ] 打开线上链接，不登录、不配置任何东西，输入「做一个记账应用」→ 60s 内看到可点击的应用
- [ ] 应用内新增一笔账单 → 刷新预览 → 数据仍在
- [ ] 说「把主色改成绿色，加一个分类饼图」→ 预览真的变了
- [ ] 制造一个运行时错误 → 浮条出现 → 一键修复后错误消失
- [ ] 生成到一半点「停止」→ 已写完的文件保留为一个新版本（标签含「中断保留」），写了一半的文件回退到旧版
- [ ] 版本时间线能看到 ≥ 3 个版本，回滚到第 1 个，预览回到初版
- [ ] 刷新浏览器、换一个浏览器重新打开 `/` → 项目仍在列表里
- [ ] 首页切到「我的」→ 只看到自己创建的项目，卡片上有「我创建的」徽章
- [ ] 导出 ZIP → 解压 → 双击 index.html 能直接运行
- [ ] 复制 `/p/:slug` 到无痕窗口 → 应用可运行
- [ ] 在设置里配置一个非法模型地址 → 「测试连接」给出明确失败原因，不崩溃
- [ ] 填一个错误的 Key 并切到云模型 → 界面弹出「模型拒绝了这个请求」+「去设置检查 Key」按钮
- [ ] 单元 + 集成测试全绿（`npm test`）

### 8.1 Atoms 四环节验收映射

评审如果只想看四件事，用这张表逐条验：

| Atoms 环节 | 验收动作 | 通过标准 | 对应用例 |
| --- | --- | --- | --- |
| ① 任务简报 | 生成过程中盯住左栏顶部 | 在任何文件出现**之前**，先出现一张方案卡，且含应用名 + 步骤 + 文件清单 | E2E-02 · IT-02 |
| ② 过程可见 | 观察生成全程 | 阶段药丸随阶段切换；文件流逐个文件出现并显示真实行数；结束后出现检查徽章 | E2E-02 · UT-PROTO-01 |
| ③ 结果可交互 | 在预览里点按钮、填表单 | 交互真实生效（不是静态图）；点「刷新预览」后数据仍在；应用内报错时宿主出现浮条 | E2E-03 · E2E-05 |
| ④ 增量修改 + 回滚 | 说「主色换成墨绿」后看版本 | 只有受影响的文件被重写（`changed[]` 非空且不含未提及文件）；版本 +1；回滚后预览回到旧版 | E2E-04 · E2E-06 · IT-04 |

**判定标准**：四个环节必须**都**能演示，缺一个就退化成"能生成代码的聊天框"。
