# 02 · 产品需求文档（PRD）

**产品名**：Nucleus Studio（原子核·造物台）
**一句话**：说一句话，得到一个能用的应用；不满意就继续说，随时能退回去。
**版本**：v1.0（笔试交付版）
**日期**：2026-11

---

## 1. 产品目标

| 目标 | 衡量方式 | 目标值 |
| --- | --- | --- |
| 冷启动零摩擦 | 首页 → 第一个应用出现的时间 | 未排队时 ≤ 90s（真实模型实测：出厂示例 51.6s、审计另一次 41.6s）；排队时先发 notice 告知预计等待，预计等待超过 90s 自动换下一家 |
| 生成可用 | 生成物在浏览器中无未捕获错误 | ≥ 90% 的生成结果首次预览无 error |
| 过程可见 | 生成过程中界面同时展示「当前阶段」与「当前文件名」 | 100% 的生成会话满足 |
| 迭代有效 | 二轮修改后错误率下降 | 100% 的修复请求至少消除 1 个已捕获错误 |
| 可交付 | 生成物能离开平台 | 100% 项目可导出 ZIP / 生成分享链接 |

**核心体验承诺**：任何一次生成，用户都能看到"它正在做什么"，任何一次失败，用户都能看到"为什么失败、下一步点哪里"。所有生成物都由**真实外部大模型**产出（默认走免 Key 通道，无需注册、无需配置），平台不做任何模板兜底；没有可用通道时就明确报 412，而不是悄悄给一个假的。

---

## 2. 角色与权限

只有一种角色：**访客（无需注册）**。

- 所有项目公开可读（Demo 定位：分享即展示）；
- 写操作不做身份隔离，但每个浏览器实例生成 `visitorId` 写入 `created_by`，仅用于 UI 上标出"我创建的"；
- 这是一个明确的权衡，见 03 文档「安全与边界」。

## 4. 功能需求

### 4.1 P0 — 基本使用流程

#### F1 创建应用（首页）

- 大输入框（多行，`⌘/Ctrl + Enter` 提交），placeholder 给示例；
- 「灵感」快捷标签 ≥ 6 个（记账 / 待办 / 番茄钟 / 看板 / 计算器 / 落地页），点击即填入；
- 提交后立即 `POST /api/projects` 建项目 → 跳转 `/studio/:id`，**不阻塞在生成上**；
- 空输入 / 超过 2000 字给出内联提示，不发请求。

#### F2 Agent 生成（工作台主流程）

生成分三段，每段在对话流里可见。三段对应 Atoms 的**任务简报 → 工程师动手 → 负责人验收**，并且全部由**真实外部大模型**产出：这一次打到谁由服务端解析链决定（见 F9），`POST /api/projects/:id/generate` 的请求体字段是 `provider`（不传 = 自动）。阶段与界面、数据的对应：

| 阶段 | 对应 Atoms 环节 | UI 表现 | 数据 |
| --- | --- | --- | --- |
| `plan` | ① 任务简报 | 一张「方案卡」：应用名、一句话简介、技术栈、步骤清单、文件清单 | `Plan` 对象 |
| `write` | ② 过程可见 | 每个文件一行，显示路径 + 行数，内容逐字流式（打字机）；当前写入的文件在代码面板高亮 | 文件 → 内容 |
| `verify` | ② 过程可见（验收） | 一组静态检查项：入口文件存在 / 引用完整性 / 外链资源 / 体积 / 沙箱安全 / **脚本语法**（每个 `.js` 一条 `syntax:<path>`，只编译不执行，抓"字符串没闭合"这类结构全绿却一打开白屏的缺陷） | `Check[]` |

- 这三段在 UI 上呈现为**活动卡片**（阶段药丸 + 逐文件流 + 检查徽章），信息全部来自真实执行结果，不使用拟态标签；
- **排队与换家要让用户看见**：免 Key 通道按提供方的最小间隔串行（FIFO 闸门），等待超过 1 秒先发一条 `notice{level:'info'}`（渲染为 `.run-notice`，内容是"前面在排队"与预计等待）；换下一家重试用 `notice{level:'warn'}`。只有终态失败才发 `error`，不再"先红一条再成功"；`done` 事件带上当次实际生效的 `provider`；
- **修复轮（最多 2 轮，`NUCLEUS_MAX_REPAIR_PASSES`）**：assemble 之后如果发现①被引用却没有输出的文件 ②闭合标签没等到的截断文件 ③语法不通的脚本，就要求模型**只**重发这几个文件，并带上具体原因；修复轮不重发方案卡（否则应用名会被占位方案覆盖），用量跨轮累计。修不动就保留当前最好的产物 + 一条 `warn` notice，不把整次生成判成失败；
- 生成过程中「发送」按钮变为「停止」，位置在输入框上方的**生成状态条**里（阶段图标 + 三段进度 + 百分比 + 当前文件 + 已用时 + 停止）；「保留已完成文件」的语义收进按钮 tooltip；
  - **语义**：连接不断开，服务端中断模型流后，把**正常闭合**的文件提交为一个新版本（标签「中断保留 · N 个文件有变化」）；写了一半的文件回退到旧版；本轮新开但没写完的文件丢弃；
  - 若没有任何文件写完，**不产生版本**（避免历史里出现空版本）；
  - 客户端通过 `done{partial:true}` 事件收到确认，并刷新预览；
- 生成完成后预览自动刷新，右侧切到「预览」，**"生成完成"与"可以立刻点"同时发生**（③ 环节要求）；
- 错误（网络 / 模型 / 协议 / 没有就绪通道）在对话流中显示为可重试的错误卡，**保留已有产物**；同时顶部弹出可操作的错误条（见 F11）。只有全链走完仍然失败才落到这张卡——排队与换家重试是 notice，不是错误。

#### F3 预览（沙箱）

- `iframe sandbox="allow-scripts allow-forms allow-modals allow-popups allow-downloads"` + `srcdoc`；
- 视口切换：桌面（100%）/ 平板（768）/ 手机（390）；
- 刷新按钮、在新窗口打开、复制分享链接；
- **常驻健康度指示灯**：工具栏上常驻显示静态自检结论（`7 项检查通过` / `2 项提醒` / `1 项阻断`），点开可看每一项的判定与详情；`block` 级失败时预览区显示占位与具体原因。

#### F4 对话迭代

- 输入框支持多轮；每轮把「当前文件集合」+「用户指令」构造成上下文；
- Agent 只需返回**变更的文件**（增量写入）；未提及的文件保持不变；
- 每次成功应用变更 → 自动落一个版本快照；
- 对话历史持久化，刷新页面后恢复。

#### F5 代码查看

- 文件树（按目录分组）+ 代码面板；
- 语法高亮（HTML/CSS/JS，自研轻量高亮，零依赖）；
- 复制当前文件、行数统计、等宽字体、暗色底。

### 4.2 P1 — 延展能力

#### F6 版本时间线

- 每个版本记录：序号、触发它的用户指令、变更文件列表、时间；
- 支持「回滚到此版本」（回滚本身也生成一个新版本，不销毁历史）；
- 支持查看某版本的文件级 diff（+ / − 行数，折叠展示）；
- **与 Atoms「还原到该消息之前的状态」的等价性**：每次成功生成恰好产生「一条 Agent 消息 + 一个版本」，二者一一对应。因此"回滚到某条消息之前"≡"回滚到该消息对应版本的上一版"——用户不需要理解版本号，只需要理解"回到刚才那次之前的样子"。

#### F7 运行时自愈

- 预览 iframe 注入错误桥：捕获 `error` / `unhandledrejection` / `console.error`；
- 右上角浮条「检测到 N 个运行时错误 · 让 Agent 修复」；
- 点击后把「错误信息 + 堆栈 + 当前代码」打包成修复指令，走 F4 的迭代链路；
- 错误去重（相同 message 只计一次），上限 20 条，避免刷屏。

#### F8 导出与分享

- 导出：`GET /api/projects/:id/export` → ZIP（项目当前版本的**全部文件**，文件名由模型在方案卡里定，例如 `index.html` / `styles.css` / `app.js`；没有 `README.md` 时服务端补一个，并把模型通道写进去）；
- 分享：`/p/:slug` 只读页，直接渲染应用，顶部一条轻量工具条（作者标识 / 模型通道 `providerLabel` / 「在 Studio 中打开」/「导出」）。导出 ZIP 后双击 `index.html` 可离线运行——这说的是**产物**自包含，与平台生成必须联网无关。

#### F9 设置

- **模型通道选择**（三段）：`自动`（交给服务端解析链，默认）/ `我的 Key`（自带 Base URL + 模型名 + Key，只对这个浏览器生效）/ **预设卡片网格**（`ready` 为假的卡片禁用，并在 `title` 与卡片上给出 `keyEnv` 与申请链接）；
- **解析链**（按尝试顺序）：① 访客自带 Key（id=`custom`）② 点名的预设 ③ 服务端目录（主力在前）④ 免 Key 通道永远兜底；没配 Key 的预设不进链。主力顺序：`NUCLEUS_PROVIDER` > 配置文件 `default` > 内联 `env` > `pollinations`；
- **内置通道**：1 条免 Key（`pollinations` · GPT-OSS 20B · `maxTokens 12000` · `reasoningEffort low` · 最小间隔 31 秒）+ 8 条需要 Key 的 OpenAI 兼容预设（DeepSeek / Gemini / Kimi / 智谱 / OpenRouter / 硅基流动 / 阿里云百炼 / 小红书 Dots）；接自家网关在 `config/providers.json` 追加一条，或用 `NUCLEUS_LLM_BASE_URL` + `NUCLEUS_LLM_MODEL`（+ `NUCLEUS_LLM_API_KEY` / `NUCLEUS_LLM_FREE=1`）合成 id=`env`；
- **Key 来源优先级**：环境变量（预设声明的 `keyEnv`，如 `DEEPSEEK_API_KEY`）> `data/providers.local.json`（已 gitignore，可放 Key）> `config/providers.json`（可入库，只调整目录结构）。服务端只回显「已配置」；
- 接口面：`GET /api/settings` 返回 `providers[]`（id / label / model / baseUrl / free / ready / isDefault / keyUrl / note / keyEnv）与 `active{ id, label, model, free }`，**不含任何 Key**；`PUT /api/settings` 的 `provider` 取 `''`（自动）/ `'custom'` / 预设 id，`apiKey` 传空串 = 清除、不传 = 保持；
- 「测试连接」按钮：发一条极短请求，测的是**解析链的第一个通道**，返回延迟、模型名与实际 `provider`；「清除我的 Key」把自带 Key 置空并交回服务端通道；部署后可以先看 `GET /api/health`——它返回主力 `provider` 与就绪通道 `providers[]`；
- 页面底部常驻「当前生效」：`active.label · active.model`；
- 设计偏好：主色（6 个预设）/ 明暗（浅色、深色、跟随系统）/ 语言（中文/English）——作为提示词参数注入每次真实生成。

#### F10 我的项目

- 首页项目区提供「全部 / 我的」切换；
- 「我的」= 只列出**当前浏览器**创建的项目（`createdBy` 与本地 `visitorId` 匹配），服务端按 `?mine=1` + `x-visitor` 头过滤；
- 自己创建的项目卡片上标「我创建的」；
- 列表默认缓存 30 秒，「刷新」按钮可强制绕过；
- **明确的边界**：这是**展示层过滤**，不是安全边界——项目公开可读、公开可写，免注册是题面要求。

#### F11 错误处置指引

- 服务端返回归一化错误码（`llm_auth` / `llm_quota` / `llm_timeout` / `llm_network` / `protocol_error` / `provider_unavailable` / `busy` / `not_found` / `bad_request` / `internal`）；
- 界面把每个错误码翻译成三段：**发生了什么**（标题）+ **为什么**（原因）+ **现在点哪里**（一个可点按钮：去设置 / 重新生成 / 回首页）；处置只有"换通道 / 修 Key / 重试"这一类，不存在退回模板的选项；
- **换家的判据**：错误码属于 `llm_auth` / `llm_quota` / `llm_timeout` / `llm_network` / `protocol_error`，**且本轮还没有任何产出**；已经吐了一半绝不换家（否则两份代码会互相覆盖）。换家发 `notice(warn)`，全链都失败才发 `error`；
- 流式过程中的 `error` 事件必须被接住并展示（不能只依赖 HTTP 抛错），否则模型 401 这类失败会变成"静默失败"。

#### F12 设计微调（视觉参数不走模型）

**为什么单独做**：换主色、调圆角是确定性变换，走一次真实模型生成要几十秒（出厂示例 51.6 秒）、还要占用免 Key 通道每 30 秒 1 次的配额，结果不可复现，并且会在版本历史里留下"只改一行 CSS"的版本。这四条都是负收益。

- 入口：预览工具栏「设计」按钮 → 面板展开（不遮挡预览）；
- 主色：6 个预设色卡 + 自定义取色器；圆角：0–28px 滑杆；
- **即时生效**：宿主 `postMessage` 把 `--accent / --accent-soft / --accent-ink / --radius` 写进沙箱 `documentElement` 的内联样式，**不重载 iframe**——应用内已填表单、列表状态、滚动位置全部保留；
- **持久化**：`PATCH /api/projects/:id {tweak}`，防抖 400ms；刷新页面后仍在；
- **一致性**：分享页与导出 ZIP 由服务端注入同一段 `<style data-nucleus="tweak">`，别人看到的和下载的与预览一致；
- **可恢复**：面板提供「恢复默认」，清除微调回到生成时的外观；
- **诚实边界**：自检里的「可用设计令牌」（`theme_vars`）改严——**必须声明 `--accent`** 才算通过；未满足时该项标红，面板提示"只能调圆角"，不假装生效；
- **生成侧配套「设计令牌契约」提示词**：主色必须写在 `--accent`、圆角必须写在 `--radius`、二者定义在 `:root`、其余位置一律用 `var()` 引用，并由主色派生 `--accent-soft` / `--accent-ink`——契约让真实模型的产物稳定可改，而不是靠事后碰运气；
- 微调是**项目级视觉状态**，不进入版本快照：回滚代码不会把配色一起回滚（两者语义不同）。

## 5. 关键交互细节

1. **流式打字机**：文件内容按 chunk 追加，渲染节流到 ~16ms/帧，避免长文件卡顿。
2. **不打断**：生成中允许切换右侧页签（预览 / 代码 / 版本），流不受影响；**切换项目会中止当前生成**（组件卸载 → SSE 断开），但服务端会把已完成的文件提交成「中断保留」版本，数据不丢。
3. **幂等**：同一项目并发两次生成时，后一次直接 409「已有生成进行中」。
4. **失败不脏数据**：生成失败不写版本、不改文件，只在对话流留一条错误。
5. **首屏性能**：首页不发模型请求；项目列表走缓存（TTL 30s，刷新按钮可强制绕过）。
6. **快捷键**：`⌘/Ctrl+Enter` 发送，`⌘/Ctrl+K` 聚焦输入框，`Esc` 停止生成（等同点「停止」，保留已完成文件）。

## 6. 状态与异常矩阵

| 场景 | 表现 | 用户可做什么 |
| --- | --- | --- |
| 解析链里没有就绪通道 | 生成前拦截：412 `provider_unavailable`，错误条说明"没有任何可用通道"（免 Key 通道在目录里永远兜底，正常走不到这一步） | 去设置配 Key / 填自己的 Key / 稍后重试 |
| 免 Key 通道排队 | 同一提供方按最小间隔（31 秒）串行；等待超过 1 秒上屏 `notice(info)`「前面在排队」，预计等待超过 `NUCLEUS_MAX_QUEUE_WAIT`（默认 90 秒）自动换下一家 | 等一会儿，或在设置里点名一个已配 Key 的通道 |
| 模型 401 / 429 / 余额不足 | **本轮还没有任何产出**时自动换解析链下一家，发 `notice(warn)`；全链失败才落错误条：「模型拒绝了这个请求」+「Key 填错、已过期或没有权限」+ 按钮「去设置检查 Key」 | 检查 Key / 换通道 / 重试 |
| 模型超时（30s 无首字节） | 同上判据：无产出则换家重试；终态失败给错误条「模型响应超时」+「首字节超过 30s 或中途断开」+ 按钮「重新生成」 | 重试 / 换通道 |
| 上游网络中断 | 同上判据（`llm_network` 属于可换家错误）；已经吐了一半**绝不换家**，避免两份代码互相覆盖 | 重试 / 换通道 |
| 协议解析失败（模型没按格式输出） | 标记 `parse_warning`，尽力恢复文件；无产出时换家，全链失败则错误条「模型没有按协议输出」 | 重试 / 换个通道 / 换个说法 |
| 产物缺文件 / 被截断 / 脚本语法不通 | 修复轮（最多 2 轮）让模型**只**重发问题文件并附具体原因；修完仍不合格 → 保留当前最好的产物 + 一条 `warn` notice，不把整次生成判成失败 | 继续对话要求补齐 / 回滚到上一版 |
| 用户主动停止 | 已写完的文件保留为新版本（标签「中断保留」），写了一半的回退到旧版 | 继续提需求 / 回滚 |
| 未生成入口文件 | 预览区占位，说明缺什么；健康度指示灯显示「1 项阻断」 | 对话要求「补一个 index.html」 |
| 运行时错误 | 浮条 + 一键修复 | 修复 / 忽略 |
| 项目不存在 | 404 页 + 回首页 | 回首页 |
| 导出失败 | toast | 重试 |

## 7. 非功能需求

| 项 | 要求 |
| --- | --- |
| 首屏 | < 1.5s（本地网络），JS 体积 < 200KB gzip（本轮构建产物：client JS 198.76 kB / gzip 65.43 kB，CSS 19.16 kB / gzip 4.62 kB，server.js 114 kB） |
