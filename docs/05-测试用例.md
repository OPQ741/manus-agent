# 05 · 测试用例与执行报告

**测试范围**：生成协议解析、模型通道目录与解析链、排队闸门与故障转移、预览组装与沙箱、持久化与版本、导出、HTTP 接口、安全校验。
**环境**：Windows 11 · Node v22 · Vitest 2.x（node 环境）· Chrome 最新版（E2E 需本机复跑）。
**运行方式**：`npm test`（单元 + 集成，随机端口起真服务；集成层所有生成都经真实 HTTP + SSE + 协议解析打到假上游）。

---

## 0. 用例设计原则

1. **测协议不测实现**：断言事件序列与产物结构，不断言内部函数调用；
2. **边界优先**：分块切割、半截标签、未闭合文件、空输入、超长输入、路径穿越；
3. **可确定性但不靠模板兜底**：内置 mock 引擎已删除，唯一的引擎是 `ModelEngine`（必须打到真实模型）。集成测试用可配置的假 OpenAI 兼容上游（`tests/fake-upstream.ts`）决定产物，于是"迭代改主色""回滚""修复轮"这些用例仍然有确定的期望值可断言 —— 测的是我们这一侧的解析、编排、落库与错误映射，不是上游；
4. **失败路径与成功路径同权**：每个错误码至少一条用例，"没有可用通道"与"上游不按协议出码"都有对应用例。

### 11.2 浏览器 E2E：`npm run e2e`（真实 Chrome）

> **本机已实跑通过（2026-11-03）**：`BASE_URL=http://127.0.0.1:8790 npm run e2e` → **14/14 步通过，3 分 0 秒**；控制台唯一一条 `pageerror` 是 E2E-05 故意抛出的「E2E 模拟运行时错误」，不计入失败。前三轮分别暴露了三个**测试自身的**脆弱点（不是产品缺陷），已就地修正并复跑确认：
>
> 1. E2E-02 的「预览不是白屏」阈值写的是 20 字符，而一个极简记账页（标题 + 三个字段 + 按钮）干净起来正好 18 个字符 → 阈值降到 8，真正判定交给「应用名必须出现 + 代码面板必须有内容 + 下一步必须能录入并持久化」。
> 2. E2E-03 只填第一个输入框，撞上生成物的必填校验（「请填写分类」）→ 改为**填满所有可填字段**（数字输入框用纯数字标记），测的才是"录入 → 落库 → 刷新还在"。
> 3. E2E-11 偶发撞上免 Key 上游「模型响应超时（30s 无数据）」→ 那一轮没有任何 `file_end`，脚本误报成"生成太快"；改为**最多重试三轮**，并把最后一次上游错误写进断言信息。

要点：

- E2E-01 断言首页项目卡标出模型出处且不再出现旧引擎徽章字样（mock 残留会被这一步抓到）。
- E2E-02/05 会**故意**触发运行时错误（`E2E 模拟运行时错误`），这是错误桥的输入而非故障，脚本在收尾单独列出、不计入失败。
- E2E-11 在 Node 侧读 SSE 精确喊停，避免浏览器轮询 DOM 的 flaky。
- 环境坑：本机开着系统代理时，Chrome 访问 `127.0.0.1` 会被代理接管导致 `ERR_CONNECTION_REFUSED`，脚本已固定传 `--no-proxy-server`。

> **已修的真实缺陷（回归项）**：编排层曾用 `result.failed ?? 默认值` 判失败，而成功时 `failed` 是**显式 null**，`??` 把 null 当缺失，导致"生成成功、文件也落库了，但前端只看到红色报错"。修复后判失败**必须先看 `result.ok`**（`server/index.ts` 注释与实现同步）。
