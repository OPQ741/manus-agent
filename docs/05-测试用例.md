# 05 · 测试用例与执行报告

**测试范围**：生成协议解析、本地引擎编译、预览组装与沙箱、持久化与版本、导出、HTTP 接口、安全校验。
**环境**：Windows 11 · Node v22.22.2 · Vitest 2.x（node 环境）· Chrome 最新版（手工 E2E）。
**运行方式**：`npm test`（单元 + 集成，随机端口起真服务）。

---

## 0. 用例设计原则

1. **测协议不测实现**：断言事件序列与产物结构，不断言内部函数调用；
2. **边界优先**：分块切割、半截标签、未闭合文件、空输入、超长输入、路径穿越；
3. **确定性**：本地引擎两次调用必须字节一致（否则无法做黄金测试）；
4. **失败路径与成功路径同权**：每个错误码至少一条用例。

### 0.1 用例与 Atoms 四环节的覆盖映射

测试不只是"代码没崩"，还要证明**四个产品环节真的成立**。下表把已有用例映射到环节上，也标出了目前只能靠手工 E2E 覆盖的部分：

| Atoms 环节 | 覆盖它的用例 | 覆盖方式 | 缺口 |
| --- | --- | --- | --- |
| ① 任务简报 | UT-PROTO-01（note→plan→file 顺序）、UT-PROTO-14（plan 非法不崩）、IT-02 | 自动化 | 方案卡与实际写入文件的一致性由 UT-COMP-12 间接覆盖 |
| ② 过程可见 | UT-PROTO-02/03（任意分块事件序列一致）、UT-PROTO-05（未闭合仍产出）、IT-02 | 自动化 | 「真实行数」只在 E2E-02 目视核对 |
| ③ 结果可交互 | UT-ASM 全组（组装/沙箱/静态检查）、IT-03、IT-05 | 自动化 + E2E | 交互真实性只能靠真实浏览器（E2E-03） |
| ④ 增量修改 + 回滚 | IT-03（迭代产生新版本且文件变化）、IT-04（回滚）、UT-STORE 版本组 | 自动化 | 回滚后的**预览一致性**由 E2E-06 覆盖 |
| 贯穿：错误自愈 | E2E-05（故意抛错 → 浮条 → 一键修复 → 清零） | E2E | — |
| 贯穿：产物带走 | UT-ZIP 全组、IT-05/IT-06、E2E-08/09 | 自动化 + E2E | — |

> 这张表的用途：评审可以直接按环节反查"哪条用例证明它"，而不是读一遍 100 多行用例表自己找。

### 11.4 未覆盖与已知限制

| 项 | 说明 |
| --- | --- |
| 真实云模型 | 环境中无可用 Key，云链路只对 mock 上游验证（IT-11/12）。填入 Key 后在 `/settings` 点「测试连接」即可确认。 |
| 多浏览器 | E2E 只跑 Chrome；Safari/Firefox 未纳入自动化，样式使用了较保守的 CSS。 |
| 长会话性能 | 单项目消息数 > 200 时未做压力测试。 |
| E2E 的"停止"时序 | E2E-11 在 Node 侧读 SSE 来精确喊停。若改成浏览器里轮询 DOM，会因生成窗口只有 ~0.7s 而 flaky。 |
| 高并发 | `Store` 为单进程串行写；多实例部署需换成外部数据库。 |
