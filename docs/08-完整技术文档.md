## 1. 系统总览

### 1.1 一次请求的完整链路

```
浏览器                                        Node 进程
─────────────────────────────────────────────────────────────────────────
POST /api/projects/:id/generate
  body: {prompt, provider?}      ─────────▶  校验（长度 / 并发锁 / 通道解析）
                                              ↓
                                    resolveChain(catalog, user) → 解析链
                                    running.set(id, AbortController)
                                    追加 user 消息
                                              ↓
                          for provider in chain:   ┌────────────────────────────┐
                            排队闸门 waitForSlot    │ attemptWith(provider)      │
                            runGeneration(ctx,     │  ModelEngine → 真实模型     │
                            ModelEngine, sink)     │  stage(plan) → plan         │──▶ 阶段药丸 + 方案卡
                                                   │  stage(write) → file_*      │──▶ 逐文件流式
                                                   │  stage(verify) → check      │──▶ 检查徽章（含语法闸门）
                                                   └────────────────────────────┘
                                              ↓  每产出一个事件
       ┌──────────────────────────────────────────┐
       │  SSE: data: {AgentEvent}\n\n             │◀────────── res.write()
       │  含 notice（排队/换家/修复轮）            │
       └──────────────────────────────────────────┘
                                              ↓  可换家且无产出 → 换下一家 + notice(warn)
                                              ↓  assemble 报缺文件/截断/语法 → 修复轮（≤2）
                                              ↓  全部完成 / 用户点「停止」
                                   store.commit(files, plan, checks, provider)
                                   追加 agent 消息
                                              ↓
       ◀──────────────────────────────────────────┤
       done(version, usage, provider) → refresh()  → 预览重新挂载
```

内置 mock 引擎已彻底删除：**唯一的引擎是 `ModelEngine`，它必须打到真实模型，打不到就直接报错（412 `provider_unavailable`），不再有"退回模板"这条路。**

### 1.2 三层分界线

| 层 | 输入 | 输出 | 不允许知道 |
| --- | --- | --- | --- |
| **引擎层** `server/agent/*`（`providers.ts` / `queue.ts` / `llm.ts` / `protocol.ts` / `runner.ts`） | `GenContext` + `ResolvedProvider` | 协议文本 / `Plan` / `AgentEvent` | HTTP、数据库 |
| **传输层** `server/index.ts` | HTTP 请求 | SSE / JSON | 生成的具体内容 |
| **进程入口** `server/main.ts` | 环境变量 | 监听 / 信号处理 | 业务逻辑（只组装） |

这条分界线带来三个好处：解析链可测、编排不碰 HTTP、`index.ts` 只导出工厂函数（import 它不会顺带占端口）。

## 3. 共享契约（`shared/types.ts`）

### 3.1 事件模型

```ts
type AgentEvent =
  | { type: 'stage'; stage: 'plan'|'write'|'verify'; status: 'running'|'done' }
  | { type: 'note'; text: string }
  | { type: 'notice'; level: 'info'|'warn'; message: string }   // 排队 / 换家 / 修复轮的过程性提示
  | { type: 'plan'; plan: Plan }
  | { type: 'file_start'; path: string }
  | { type: 'file_delta'; path: string; chunk: string }
  | { type: 'file_end'; path: string; lines: number; content: string; truncated?: boolean }
  | { type: 'delete'; path: string }
  | { type: 'check'; check: Check }
  | { type: 'warning'; message: string }
  | { type: 'done'; version: number; usage: Usage; provider?: ProviderInfo; partial?: boolean; kept?: number }
  | { type: 'error'; code: ApiErrorCode; message: string }
```

| 字段 | 语义 |
| --- | --- |
| `notice` | 描述"此刻在发生什么"，不是红色错误、不进版本历史。info（灰）如排队提示、修复轮开始；warn（红）如换家、修完仍有问题 |
| `file_end.truncated` | `true` 表示这个文件**没有正常闭合**（流断了 / 模型忘了写 `</file>`）。「中断保留」据此判断哪些文件算「写完了」；截断文件也会驱动修复轮 |
| `done.provider` | 这次实际用了哪家模型（`ProviderInfo`：id/label/model/free） |
| `done.partial` | `true` 表示这次是用户主动停止后保留的版本，不是完整生成；`kept` 是保留下来的文件数 |
| `done.version` | 服务端提交后的版本号；`runner` 内部产生的 `done`（version=0）不会转发给前端 |

### 3.2 数据结构

```ts
Project {
  id, slug, name, summary,
  provider: ProviderId,          // 最近一次成功生成用的提供方 id（原 engine 字段已删）
  providerLabel: string,         // 展示名（"免 Key · GPT-OSS 20B"），落库时定死，避免目录变更后历史标签漂移
  design: { accent, theme, locale },
  tweak?: DesignTweak,           // 设计微调（叠加在生成结果之上，不进入版本快照）
  files: FileEntry[], plan, checks, version,
  createdBy, createdAt, updatedAt
}

Usage { ms, provider: ProviderId, chars, tokens? }   // engine 字段已改为 provider
ProviderInfo { id, label, model, free }
ProviderId = string   // 契约：从 EngineId('local'|'cloud') 退化为"这次用的是哪一家"，可被 config/providers.json 扩展

Plan   { name, summary, stack, steps: string[], files: {path, purpose}[] }
Check  { id, label, ok, level: 'block'|'warn'|'info', detail? }
Version{ id, projectId, seq, label, prompt, files: FileEntry[], changed: string[], createdAt }
Message{ id, projectId, role: 'user'|'agent'|'system', kind: 'text'|'plan'|'error'|'notice',
         content, meta?, createdAt }
```

## 4. 生成协议 NWF

### 4.1 语法

```
<note>自由文本，作为 Agent 口播</note>
<plan>{"name":"…","summary":"…","stack":"…","steps":[…],"files":[{"path":"…","purpose":"…"}]}</plan>
<file path="index.html">
（原始内容，不转义）
</file>
<delete path="old.js"/>
```

### 4.2 状态机

```
      ┌────────┐  <plan>   ┌──────┐  </plan>  ┌────────┐
      │ OUTSIDE│──────────▶│ PLAN │──────────▶│ OUTSIDE│
      └────────┘           └──────┘           └────────┘
           │ <file path>                ▲
           ▼                            │ </file>
      ┌────────┐  任意字符（累积）        │
      │  FILE  │────────────────────────┘
      └────────┘
```

实现要点：

- 维护 `buffer`，每次 `push(chunk)` 循环匹配"下一个标签"，**只处理已完整到达的标签**，半截留在 buffer；
- `<` 开头但构不成标签的字符退化为正文（容忍模型写 `a < b`）；
- `push()` 与 `end()` **永不抛异常** —— 所有异常路径降级为 `warning` 事件；
- 逐字符喂入与整体喂入产出**完全一致**的事件序列（UT-PROTO-02/03 用随机分块断言）。

### 4.3 漂移纠正（`protocol.ts` / `llm.ts` 的流处理）

| 漂移 | 纠正 |
| --- | --- |
| 用 ` ```html ` 包裹整个 `<file>` | `file_end` 时剥围栏 |
| 写成 `<file name="a.html">` | 属性名兼容 `name` / `filename` |
| 大小写 `<FILE PATH=…>` | 标签名与属性名转小写后匹配 |
| 忘记 `</file>` 直接开下一个 `<file>` | 收尾前一个并标 `truncated`，产生 warning |
| 输出正文前有元话语 | OUTSIDE 状态自动归入 note |

**纠正只发生在格式层**：不重试整轮、不改写代码内容、不猜测缺失文件（缺文件交给修复轮，见 §6.2）。

### 4.4 路径安全

`sanitizePath()` 白名单：`[A-Za-z0-9_\-.]` 与 `/`；拒绝 `..`、绝对路径、空段、以 `.` 开头的段、超长路径。非法路径 → 丢弃该文件 + warning。

## 5. 引擎层

### 5.1 接口

```ts
interface AgentEngine {
  id: ProviderId
  info: ProviderInfo
  plan(ctx: GenContext): Promise<Plan>
  write(ctx: GenContext): AsyncIterable<string>   // 原始协议文本
}
```

唯一实现是 `ModelEngine`：把上游的增量原样上抛，协议解析留给上层。`plan()` 只做占位方案（不调模型，从需求里捞应用名，让用户在首字节前就看到"它在做什么"）。

### 5.2 模型通道目录（`providers.ts`）

这一层只回答一个问题：**这一次生成该打给谁。**

7 条内置预设（`BUILTIN_PROVIDERS`），只有第一条免 Key：

| id | 标签 | 模型 | Key 来源 | 备注 |
| --- | --- | --- | --- | --- |
| `pollinations` | 免 Key · GPT-OSS 20B | `openai-fast` | 免 Key（`free`） | maxTokens 12000、reasoningEffort `low`、minIntervalMs 31000（匿名档约每 30 秒 1 次） |
| `deepseek` | DeepSeek V3 | `deepseek-chat` | `DEEPSEEK_API_KEY` | |
| `gemini` | Gemini 2.5 Flash | `gemini-2.5-flash` | `GEMINI_API_KEY` | 有免费档 |
| `moonshot` | Kimi K2 | `kimi-k2-0905-preview` | `MOONSHOT_API_KEY` | 国内直连 |
| `zhipu` | GLM-4.5-Air | `glm-4.5-air` | `ZHIPU_API_KEY` | |
| `openrouter` | OpenRouter 聚合 | `deepseek/deepseek-chat` | `OPENROUTER_API_KEY` | 带 http-referer/x-title 头 |
| `siliconflow` | 硅基流动 · Qwen3 Coder | `Qwen/Qwen3-Coder-30B-A3B-Instruct` | `SILICONFLOW_API_KEY` | 出码类 |

**Key 来源优先级**：环境变量（每条预设的 `keyEnv`）> `data/providers.local.json`（gitignore，可放 Key）> `config/providers.json`（可入库，按 id 逐字段合并，**不能凭空造免 Key**）。

**内联预设**：`NUCLEUS_LLM_BASE_URL` + `NUCLEUS_LLM_MODEL`（+ `NUCLEUS_LLM_API_KEY` / `NUCLEUS_LLM_FREE=1` / `NUCLEUS_LLM_LABEL` / `NUCLEUS_LLM_MAX_TOKENS` / `NUCLEUS_LLM_TEMPERATURE`）合成 `id=env`，地址非法则整条忽略，存在即自动成为主力。

**主力选择优先级**：`NUCLEUS_PROVIDER` > 内联 `env` > 配置文件 `default` > `pollinations`（免 Key 兜底）。内联网关排在仓库配置文件之前：部署者显式给了 `NUCLEUS_LLM_BASE_URL`，这个意图比一份随代码提交的 `default` 更强。

**解析链（`resolveChain`，按尝试顺序）**：① 访客自带 Key（`id=custom`，只对他自己生效）② 点名的预设 ③ 服务端目录（主力在前）④ 免 Key 永远兜底。未就绪的不进链；按 id 去重；全链为空 → 412 `provider_unavailable`。

`catalogView()` 给 UI 的目录视图**永远不含 Key**。

### 5.3 排队闸门（`queue.ts`）

免 Key 通道（Pollinations 匿名档）实测为**同一 IP 每 30 秒 1 次**，线上服务端只有一个出口 IP = 全站共享这一条配额。`waitForSlot(providerId, {minIntervalMs, maxWaitMs, signal})`：

- 按提供方 `minIntervalMs` 把并发请求排成 FIFO（判定等待与推进 `nextAt` 在同一同步块，避免抢槽）；
- 预计等待 > `NUCLEUS_MAX_QUEUE_WAIT`（默认 90 秒）抛 `QueueFullError`，让编排层换下一家 —— **被拒的请求不推进 `nextAt`，不会把后面的人一起推后**；
- 等待途中被 abort 立刻退出；`projectedWait()` 给 UI 显示"前面还有几个人"。

### 5.4 云端客户端（`llm.ts`）

OpenAI 兼容：`POST {baseUrl}/chat/completions`，`stream: true`，逐帧解 `choices[0].delta.content`，末帧带 `usage.total_tokens` 时回报 token。

| 事项 | 实现 |
| --- | --- |
| SSRF 防护 | 只允许 http/https；拒绝 `localhost` / `127.` / `10.` / `172.16-31.` / `192.168.` / `169.254.` / `[::1]`（测试钩子 `NUCLEUS_ALLOW_LOCAL_LLM=1` 可临时放开） |
| 超时 | 首字节 30s；空闲 60s；两者分开，避免"卡住"和"慢"混为一谈 |
| 错误码归一 | 401/403 → `llm_auth`；429/402 → `llm_quota`（带 `Retry-After`）；其余 → `llm_network`；超时 → `llm_timeout` |
| `max_tokens` / `reasoning_effort` | 显式带上。实测上游默认只给 1500 completion tokens（含思考链），不传会把四文件应用从中间截断；gpt-oss 是思考型模型，`reasoning_effort` 只支持 high/medium/low（`minimal` 返 400），默认强度正文常写不完，所以预设固定 `low` |

单个坏帧（JSON 解析失败）被跳过，不中断整条流。

### 5.5 上下文选择策略（`prompts.ts`）

迭代轮要把当前文件回传给模型。预算 `MAX_CONTEXT_CHARS = 24000`。

**旧策略的问题**：按路径顺序累加，超预算后剩下的文件**整份消失** —— 模型会以为那个文件不存在，于是把它整个重建。

**现在的策略**：

1. **打分**：语义类别亲和度（分路径权重）+ 词法命中 + 入口文件保底分；
2. **选取**：按分数降序（同分按体积升序），放得下就完整放，放不下就**截断**而不是丢弃（截断后至少给 600 字符，否则跳过）；
3. **保底**：入口文件始终有基础分，模型至少看得到页面骨架；
4. **manifest**：上下文里附一份清单，列出**全部**文件及其状态（完整 / 已截断 / 未提供内容）。

提示词约束（"提示词约定"，与服务端硬预算分开）：文件数 **≤ 5**、单个文件 **≤ 400 行**、必须有 `index.html`、CSS/JS 用相对路径引用、零构建、无外部依赖（必要时仅 CDN 外链并做降级）。

**设计令牌契约**（提示词强制）：主色写成 `--accent`、圆角写成 `--radius`，都定义在 `:root`，其余一律用 `var()`，并派生 `--accent-soft`（浅底）与 `--accent-ink`（主色上的文字色）—— 这样平台的"实时改主色/圆角"才不用重新生成代码。

**修复轮提示词**（`repairMessages`）：只重发被点名的文件、每个都完整可运行、带具体失败原因、禁止重写其它文件（否则版本历史变成无意义全文替换）。

## 6. 编排层（`runner.ts` + `index.ts` 的 `handleGenerate`）

### 6.1 单轮事件流（`runGeneration`）

```
runGeneration(ctx, engine, sink)
  ├─ stage(plan, running) → engine.plan() → plan 事件 → stage(plan, done)   // 修复轮不重发方案
  ├─ stage(write, running)
  │    └─ for await (chunk of engine.write())  → parser.push → 逐事件转发
  ├─ parser.end() → 收尾未闭合的文件（标 truncated）
  ├─ stage(write, done)
  ├─ 若一个文件都没有 → error(protocol_error) + 附原文前 180 字
  ├─ stage(verify) → assemble(files) → check 事件 × N（含每个 .js 一条 syntax 检查）
  └─ done(version=0, usage, provider)   // 不转发给前端，真正的 version 由路由层提交后给出
```

`GenSink` 记录本轮产物：`files`、`completed`（正常闭合的路径）、`deleted`、`plan`、`checks`、`warnings`、`missing`（被引用但没输出）、`broken`（语法不通的脚本）、`truncated`（闭合标签没等到）、`raw`、`usage`。

### 6.2 故障转移（`index.ts` 逐家尝试 + `runner.ts` 的 `canFailover`）

对解析链逐家调用 `attemptWith`。**可换家判据**（`canFailover`）：错误码 ∈ {`llm_auth`,`llm_quota`,`llm_timeout`,`llm_network`,`protocol_error`} 且**本轮还没有任何产出**（`raw` 为空且没有已写完文件）；**已经吐了一半绝不换家**（否则两份代码互相覆盖）。

- 换家时发一条 `notice(level:'warn')`「这家不行，正在换下一家」；
- 中间失败**不立即发红色 error**（避免"先红一条再成功"）；只有整条链都终态失败才发 `error`；
- `QueueFull`（等不起免 Key 配额）不算失败，只是这家太挤，交给编排层换下一家；
- 失败判定**必须先看了 `result.ok`**，不能用 `result.failed ?? 默认值` —— 成功时 `failed` 是显式 `null`，`??` 会把 null 当缺失，导致"生成成功、文件也落库了，但前端只看到红色报错"（真踩过的坑）。

### 6.3 修复轮（`index.ts` 的 repair pass）

`assemble` 后若发现三类"生成了但不完整"，就要求模型**只**重发这些文件、并带上具体原因：

1. `missing`：被引用但没输出的文件；
2. `truncated`：闭合标签没等到、写到一半被截断的文件；
3. `broken`：语法就不通的脚本。

规则：最多 `NUCLEUS_MAX_REPAIR_PASSES`（默认 2）轮；修复轮不重发方案卡（否则占位方案会把已定稿的应用名覆盖）；用量跨轮累计；修不动就**保留当前最好的产物 + 一条 warn `notice`**，而不是把整次生成判失败。

### 6.4 中断保留语义

用户点「停止」时，客户端**不关闭 SSE**，而是调 `POST /api/projects/:id/stop`：

```
POST /stop → running.get(id).abort()
            → aborted = signal.aborted
            → partialFiles(sink, previous)：
                · completed 里的文件 → 用新内容
                · 写了一半的文件   → 回退到旧内容
                · 本轮新开没写完的 → 直接丢弃
                · deleted 里的      → 保持删除
            → 有变化 → commit(label "中断保留 · N 个文件有变化")
            → 无变化 → 不产生版本（避免历史里全是空版本）
            ◀ done(version, partial:true, kept)
```

客户端断开时服务端同样会提交已完成部分 —— 数据不会因为"手快关掉页面"而丢失。

## 7. 预览组装与沙箱（`preview/assemble.ts`）

### 7.1 组装算法

输入 `FileEntry[]`，输出 `{html, entry, checks, inlined, missing, broken}`：

1. 选入口：`index.html` → `index|main|app*.html` → 第一个 `.html`；
2. 内联 CSS：`<link rel="stylesheet" href="styles.css">` → `<style data-src="styles.css">…</style>`（**保持原位置**，保证层叠顺序）；
3. 内联 JS：`<script src="app.js"></script>` → `<script data-src="app.js">…</script>`（保持原位置，保证执行顺序）；
4. 注入错误桥 + storage shim（插在 `<head>` 之后、业务脚本之前）；
5. 若有设计微调，在 `</head>` 前注入 `<style data-nucleus="tweak">`（后写者胜，无需 `!important`）；
6. 产出静态检查（含脚本语法闸门）。

### 7.2 静态检查项

| id | 标签 | 级别 | 判定 |
| --- | --- | --- | --- |
| `entry` | 入口文件存在 | block | 存在入口 HTML |
| `refs` | 引用完整性 | warn | 所有相对引用都存在（否则记入 `missing`） |
| `structure` | HTML 结构完整 | warn | 含 `<html>` 与 `<body>` |
| `size` | 体积在预算内 | warn | 总字节 ≤ `MAX_TOTAL_BYTES`(400KB) |
| `external` | 外部依赖检查 | info | 列出 CDN 外链（离线不可用）；无外链则"完全自包含，可离线运行" |
| `sandbox_safe` | 沙箱越权检查 | warn | 不含 `parent.document` / `top.location` 等 |
| `theme_vars` | 可用设计令牌 | info | **必须声明 `--accent` 才 ok**；只有 `--radius` 时如实说"主色需要重新生成" |
| `syntax:<path>` | `<path> 语法` | block | 每个 `.js` 一条，`new Function` 只编译不执行（否则记入 `broken`） |

**语法闸门是本轮新增的关键**：一个写到一半没闭合的字符串会让整个应用静默白屏，而结构检查全是绿的。`scriptSyntax()` 用 `new Function` **只编译不执行** —— 既抓语法错误，又不运行生成物代码。`block` 级失败会挡住预览；`warn` / `info` 只提示。结果同时出现在：对话流的检查徽章 + 预览工具栏的**常驻健康度指示灯**。

### 7.3 错误桥

注入到每个预览文档最前面：`addEventListener('error'/'unhandledrejection')`、包装 `console.error`、`post({kind:'ready'})`，并处理宿主下发的 `__nucleus_tweak`（改 CSS 变量而不重载 iframe）。父窗口只信任带 `__nucleus: 1` 标记的消息。

### 7.4 storage shim 与回灌

沙箱是**不透明源**（没有 `allow-same-origin`），原生 `localStorage` 会抛 `SecurityError`：

```
生成的应用 → shim.setItem() → postMessage({kind:'storage', op:'set'})
                                    ↓
宿主（src/lib/seed.ts） → 写进浏览器 localStorage（键：nucleus.seed.<projectId>）
                                    ↓
重新挂载预览 → withSeed() 把种子写进 <head> 之后的 window.__NUCLEUS_SEED
                                    ↓
                        沙箱内 shim 初始化时读种子 → "刷新数据还在"
```

## 8. 持久化与版本（`store/store.ts`）

### 8.1 原子写与 schema

```ts
const tmp = `${file}.${process.pid}.tmp`
await fs.writeFile(tmp, JSON.stringify(db), 'utf8')
await fs.rename(tmp, file)          // 同分区 rename 是原子的
```

- 单进程内用**串行写队列**防并发撕裂；
- `Database.schema = 2`（v1 的 `engine: 'local'|'cloud'` 与 mock 引擎预置项目已被 provider 契约取代）。读到旧 schema 时**备份为 `db.json.v1-backup.<ts>` 并重建**，再载入出厂示例（顺带清掉线上原先 10 个 mock 项目）；
- 文件损坏时改名备份为 `db.json.corrupt.<ts>` 后重建；
- `seedDatabase()` 只在项目列表为空时载入 `factory-example.json`，**不在启动时调模型**。

### 8.2 版本模型

- `generate` / `rollback` 成功后落一份**完整文件快照** + `changed[]`；
- `rollback(seq)`：把目标版本复制成**新版本**（label `回滚至 vN`），历史不删；
- 裁剪：单项目版本超过 30 时，保留首版 + 最近 5 版。

### 8.3 容量与硬预算

**服务端硬预算**（与 §5.5 提示词约定分开，二者不要混写）：

| 对象 | 上限 | 常量 |
| --- | --- | --- |
| 文件数 | 24 | `MAX_FILES` |
| 单文件 | 200 KB | `MAX_FILE_BYTES` |
| 单项目总量 | 400 KB | `MAX_TOTAL_BYTES` |
| 需求描述 | 2000 字 | `PROMPT_MAX_LENGTH` |
| 上下文回传 | 24000 字符 | `MAX_CONTEXT_CHARS` |
| 消息 | 每项目 80 条 | 超出丢最旧 |
| 版本 | 每项目 30 个 | 保留首版 + 最近 5 版 |

> 提示词里要求模型"文件数 ≤ 5、单文件 ≤ 400 行"，是**给模型的约定**；服务端 `MAX_FILES=24 / 单文件 200KB / 总量 400KB` 是**兜底的硬预算**，`size` 检查用的就是后者。

### 9.2 设置接口字段

`GET /api/settings` 返回：

- `providers[]`：每条 `{id, label, model, baseUrl, free, ready, isDefault, keyUrl?, note?, keyEnv?}`（`keyEnv` 免 Key 时为 undefined），**不含任何 Key**；
- `active{id, label, model, free}`：这一次实际会打给谁（自带 Key 时是 custom，否则服务端主力）；
- `hasKey` / `apiKeyMasked`：访客自带 Key 的掩码，绝不回显明文。

`PUT /api/settings` 接受：

- `provider`：`''`（自动）/ `'custom'` / 预设 id；
- `apiKey`：**传空串 = 清除、不传该键 = 保持**（少了这条，访客换到服务端预设后旧 Key 会一直悄悄优先）；
- `model`：限 80 字符；`baseUrl`：过 SSRF 校验；`design`：局部覆盖。

`POST /api/settings/test` 测的是**解析链的第一个通道**（自带 Key 优先），成功返回 `{ok, ms, sample, model, provider}`，无通道 412、上游失败 502 `{ok:false, error, message}`。

### 9.3 SSE 帧格式

```
data: {"type":"notice","level":"info","message":"… 前面还有约 N 秒排队，正在等它…"}

data: {"type":"stage","stage":"plan","status":"running"}

data: {"type":"plan","plan":{"name":"随手记账", …}}

data: {"type":"file_end","path":"index.html","lines":128,"content":"…","truncated":false}

data: {"type":"check","check":{"id":"syntax:app.js","ok":true,"level":"block"}}

data: {"type":"notice","level":"warn","message":"… 这次不可用，正在换下一家（…）…"}

data: {"type":"done","version":2,"usage":{"ms":812,"provider":"pollinations","chars":20480,"tokens":6327},"provider":{"id":"pollinations","label":"免 Key · GPT-OSS 20B","model":"openai-fast","free":true}}

data: {"type":"error","code":"llm_auth","message":"模型拒绝请求（401）：invalid api key"}
```

请求级 catch：若异常发生在**已开始流式输出之后**，会补发一帧 `{type:'error', code:'internal'}` 并打日志 —— 避免"事件流戛然而止、没有 done 也没有 error"这类最难查的故障（旧实现是静默 `res.end()`）。

### 9.4 错误码

| code | HTTP | 含义 | 前端动作 |
| --- | --- | --- | --- |
| `bad_request` | 400 | 参数非法（空 prompt、超长、非法 JSON、内网 Base URL、非法方法 405） | 就地提示 |
| `not_found` | 404 | 项目/版本/分享链接/路由不存在 | 回首页 |
| `busy` | 409 | 该项目已有生成进行中 / 空闲时点停止 | 等待或停止 |
| `provider_unavailable` | 412 | 没有任何就绪模型通道（免 Key 被关掉且没自带 Key）；`done.usage` 也不会有 | 去设置 |
| `llm_auth` | SSE error | Key 无效/无权限 | 去设置 |
| `llm_quota` | SSE error | 额度或限流 | 重试 / 换 Key |
| `llm_timeout` | SSE error | 首字节/空闲超时 | 重试 |
| `llm_network` | SSE error | 连不上上游 | 去设置 |
| `protocol_error` | SSE error | 模型没按协议输出任何文件 | 重试 / 换家 |
| `internal` | 500 / SSE error | 兜底 | 重试 |

前端的映射表在 `src/lib/errors.ts`：每个错误码 → **标题 + 原因 + 一个可点按钮**（去设置 / 重新生成 / 回首页）。旧的引擎二选一错误码已由 `provider_unavailable` 取代，且不再出现"改用模板"的文案。

### 10.2 状态管理

| 规则 | 原因 |
| --- | --- |
| `live.files` 与 `project.files` 分离 | 流式期间显示 live，`done` 后以服务端返回的项目为准 |
| 打字机节流 | `file_delta` 先入队，`requestAnimationFrame` 批量 flush |
| `notice` 只保留最新一条 | 它描述"此刻在发生什么"，渲染为 `.run-notice`（info 灰、warn 红） |

| 项目列表缓存 | 30s TTL，`force` 可绕过 |

徽章文案：首页/分享/工作台的模型徽章都取 `project.providerLabel`（回落到 `active.label` 或"模型生成"），不再是旧的引擎二选一徽章。

### 10.3 SSE 消费（`src/lib/api.ts`）

逐块 `reader.read()` → 累积 buffer → 按 `\n\n` 切帧 → 逐行取 `data:` 前缀 → `JSON.parse`。**坏帧跳过，不打断整条流**。

## 11. 安全模型

| 面 | 威胁 | 对策 |
| --- | --- | --- |
| 生成代码执行 | 读取宿主 DOM / cookie / 接口 | `iframe sandbox` **不含** `allow-same-origin` → 不透明源 |
| 生成物持久化 | 沙箱内 storage 不可用 | 内存 shim + 宿主回灌（§7.4），数据不出浏览器 |
| 路径穿越 | `../etc/passwd` 写入/导出 | `sanitizePath` 白名单；导出时二次校验；静态服务前缀校验 |
| XSS（平台自身） | 模型输出或用户输入注入 | 不使用 `dangerouslySetInnerHTML` 渲染原始文本；高亮**先切词再 escape** |
| API Key 泄露 | Key 出现在前端或日志 | Key 只存服务端；`catalogView`/设置响应只回显掩码；接口/目录**不含 Key**；不写日志 |
| SSRF | 用 Base URL 探测内网 | 只允许公网 http(s)，拒绝内网网段（白名单不变；测试钩子 `NUCLEUS_ALLOW_LOCAL_LLM=1`） |
| 访客 Key 串扰 | 一个访客的 Key 影响别人 | 自带 Key 只进入**这一次解析链**（`id=custom`），只对他自己生效 |
| 提示词注入 | 用户输入里写 `</file>` 撑破上下文 | `sanitizeUserPrompt` 把定界符转义为全角并截断 |
| 并发竞态 | 同一项目两次生成互相覆盖 | `running` Map 做项目级互斥，第二个请求 409 |
| 写响应后连接已关闭 | 客户端断开后继续 `res.write` → `ERR_STREAM_DESTROYED` | `send()` 检查 `clientGone / writableEnded / destroyed`；`res.on('error')` 吞掉写错误 |
| 语法坏掉静默白屏 | 未闭合字符串"看起来成功" | `assemble` 语法闸门（只编译不执行）作为 block 检查 + 修复轮 |
| 数据隔离 | 无账号体系 | **明确取舍**：项目公开可读可写，`createdBy` 仅 UI 标记，不是安全边界 |

### 13.3 三种部署形态

1. **零配置免 Key**：什么都不设。解析链默认主力是 `pollinations`（免 Key），打开即用；受匿名档配额（约每 30 秒 1 次）限制，多人会排队。
2. **服务端预设**：设 `NUCLEUS_PROVIDER=deepseek` + `DEEPSEEK_API_KEY=…`（或写进 `config/providers.json` 的 `default`，Key 走对应 `keyEnv` 环境变量）。访客无需自带 Key 也能用上稳定主力。
3. **内联 env 网关**：设 `NUCLEUS_LLM_BASE_URL` + `NUCLEUS_LLM_MODEL`（+ `NUCLEUS_LLM_API_KEY`，或 `NUCLEUS_LLM_FREE=1` 表免 Key 网关），合成 `id=env` 并自动成为主力 —— 接任意 OpenAI 兼容网关而不改代码。

`config/providers.json`（可入库）只调目录结构、**不放 Key**；本地开发要放 Key 写 `data/providers.local.json`（已 gitignore）。

### 13.4 数据与备份

- 全部状态在 `data/db.json` 一个文件里 → **备份 = 复制这个文件**；**重置 = 删掉它**（下次启动重建并载入 1 个出厂示例）；
- 读到旧 schema 会先备份成 `db.json.v1-backup.<ts>` 再重建；
- 生成的应用里的数据在**访客浏览器**里，不在服务端；访客 Key 只在服务端。

### 13.5 排障手册

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 打开页面提示「前端产物未构建」 | `dist/client` 不存在 | 跑 `npm run build` |
| 首页空白、无项目 | `data/db.json` 损坏 | 看 `db.json.corrupt.<ts>` 备份；删掉 `db.json` 重启 |
| 412 `provider_unavailable` | 免 Key 被 `enabled:false` 关掉且没自带 Key | 恢复免 Key 或选一个已就绪预设 / 填 Key |
| 生成一直转圈 | 上游连不上 / 排队 | 设置页「测试连接」；检查地址与网络；换一家 |
| "脚本语法不通"阻断项 | 模型写到一半 | 正常会自动修；仍坏就换更强的模型或更具体的需求 |
| 点「停止」没反应 | 生成已结束 | 正常；按钮只在生成中可见 |
| 预览打不开 | 缺入口文件 | 对话里说「补一个 index.html」 |
| `/api/...` 返回 409 | 同项目已有生成在进行 | 等它结束或点「停止」 |
| 设置页保存失败 400 | Base URL 指向内网 | 换公网地址 |

### 13.6 部署形态（进程）

单进程 + 本地磁盘：容器内 `npm install && npm start`，暴露 `PORT`。静态资源与 API 同源，无 CORS、无预检。多实例部署需换成外部数据库（`Store` 接口已预留，见 §15.3）—— 且排队闸门是单进程内存态，同样只在单进程下成立。

## 15. 扩展指南

### 15.1 加一家模型（不必改代码）

两种途径：

1. 在 `config/providers.json` 的 `providers` 数组里追加一条同形状对象：
   ```json
   { "id": "mygateway", "label": "我的网关", "baseUrl": "https://gw.example.com/v1",
     "model": "some-model", "keyEnv": "MY_GATEWAY_API_KEY", "maxTokens": 8192 }
   ```
   再注入 `MY_GATEWAY_API_KEY` 环境变量即可就绪；把它设成 `default` 或 `NUCLEUS_PROVIDER` 就成主力。
2. 直接给某个内置预设填 Key：设它声明的 `keyEnv`（如 `DEEPSEEK_API_KEY`）。

配置文件**按 id 逐字段合并**：只改 `model` 不会抹掉 `label`/`keyEnv`/配额说明；`enabled:false` 可彻底摘掉一家；非内置条目不能凭空声明 `free`（免 Key 只信任内置预设）。

### 15.2 换成真沙箱（E2B / WebContainer）

只需替换两处：`server/preview/assemble.ts` 的 `assemble()`（写进沙箱、取回预览 URL）与 `src/components/PreviewPanel.tsx` 的渲染分支（`srcdoc` → `src`）。事件模型、`AgentEvent`、对话流、版本逻辑**都不用动**。

### 15.3 换持久化

实现 `Store` 的方法集（`listProjects` / `getProject` / `getBySlug` / `createProject` / `updateProject` / `deleteProject` / `listMessages` / `appendMessage` / `listVersions` / `getVersion` / `commit` / `rollback` / `getSettings` / `updateSettings` / `detail`），把单文件 JSON 换成 Postgres 即可。注意保留两个语义：`commit()` 必须整份快照；`listProjects(mine?)` 是展示层过滤而非安全边界。换多实例还要把 `queue.ts` 的内存闸门换成共享存储。

### 15.4 加一个静态检查项

在 `assemble()` 的 `checks.push(...)` 加一项 → 前端自动显示（对话流徽章 + 健康度指示灯）。

### 15.5 加一个页面

`src/App.tsx` 的路由表加一条 → 新建 `src/pages/Xxx.tsx` → 需要数据就往 `src/lib/api.ts` 加一个方法 + 服务端加一条路由。

## 16. 已知限制

| 限制 | 根因 | 解除条件 |
| --- | --- | --- |
| 单进程存储 | 本地文件 + 串行写队列 | 换 Postgres（§15.3） |
| 排队闸门单进程内存态 | 与持久化同约束 | 多实例时换共享存储 |
| 不支持构建型产物 | 纯前端沙箱没有构建步骤 | 执行层换真沙箱（§15.2） |
| 上下文预算 24000 字符 | 迭代轮全量回传文件 | 已做相关度排序 + 截断；再进一步需检索式上下文 |
| 无身份体系 | 题面要求免注册 | 需要账号体系时再加（`createdBy` 已留字段） |
| 沙箱无同源 | 安全要求 | 重新设计隔离模型 |
| 免 Key 通道有配额 | 匿名档约每 30 秒 1 次 | 填 Key / 服务端预设 / 换家 |
| 一次生成不保证 100% 完整 | 模型可能缺文件/截断/语法坏 | 语法闸门 + 修复轮（≤2）+ 保留最好产物；更强模型或更具体需求 |
| 只跑 Chrome 的 E2E | 自动化环境限制 | 补 Safari/Firefox |
| 线上仍是修复前版本 | 本轮改动未部署 | **需重新部署**后方能体现 |
