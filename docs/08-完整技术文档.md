## 1. 系统总览

### 1.1 一次请求的完整链路

```
浏览器                                        Node 进程
─────────────────────────────────────────────────────────────────────────
POST /api/projects/:id/generate
  body: {prompt, engine?}        ─────────▶  校验（长度 / 并发锁 / 引擎配置）
                                              ↓
                                         running.set(id, AbortController)
                                         追加 user 消息
                                              ↓
                                    ┌─────────────────────────────┐
                                    │ runGeneration(ctx, engine,  │
                                    │             sink)          │
                                    │  stage(plan) → plan         │──▶ 阶段药丸 + 方案卡
                                    │  stage(write) → file_*      │──▶ 逐文件流式
                                    │  stage(verify) → check      │──▶ 检查徽章
                                    └─────────────────────────────┘
                                              ↓  每产出一个事件
       ┌──────────────────────────────────────────┐
       │  SSE: data: {AgentEvent}\n\n             │◀────────── res.write()
       └──────────────────────────────────────────┘
                                              ↓  全部完成 / 用户点「停止」
                                   store.commit(files, plan, checks)
                                   追加 agent 消息
                                              ↓
       ◀──────────────────────────────────────────┤
       done(version, usage)  →  refresh() 拉项目  →  预览重新挂载
```

### 1.2 三层分界线

| 层 | 输入 | 输出 | 不允许知道 |
| --- | --- | --- | --- |
| **引擎层** `server/agent/*` | `GenContext` | 协议文本 / `Plan` | HTTP、数据库 |
| **编排层** `server/agent/runner.ts` | `GenContext` + `AgentEngine` | `AgentEvent` 流 + `GenSink` | HTTP、数据库 |
| **传输层** `server/index.ts` | HTTP 请求 | SSE / JSON | 生成的具体内容 |

这条分界线带来三个好处：换引擎不动上层、加新引擎只实现一个接口、测试可以拿假事件直接驱动 UI。

## 3. 共享契约（`shared/types.ts`）

### 3.1 事件模型

```ts
type AgentEvent =
  | { type: 'stage'; stage: 'plan'|'write'|'verify'; status: 'running'|'done' }
  | { type: 'note'; text: string }
  | { type: 'plan'; plan: Plan }
  | { type: 'file_start'; path: string }
  | { type: 'file_delta'; path: string; chunk: string }
  | { type: 'file_end'; path: string; lines: number; content: string; truncated?: boolean }
  | { type: 'delete'; path: string }
  | { type: 'check'; check: Check }
  | { type: 'warning'; message: string }
  | { type: 'done'; version: number; usage: Usage; partial?: boolean }
  | { type: 'error'; code: ApiErrorCode; message: string }
```

| 字段 | 语义 |
| --- | --- |
| `file_end.truncated` | `true` 表示这个文件**没有正常闭合**（流断了 / 模型忘了写 `</file>`）。「中断保留」据此判断哪些文件算「写完了」 |
| `done.partial` | `true` 表示这次是用户主动停止后保留的版本，不是完整生成 |
| `done.version` | 服务端提交后的版本号；`runner` 内部产生的 `done`（version=0）不会转发给前端 |

### 3.2 数据结构

```ts
Project {
  id, slug, name, summary, engine,
  design: { accent, theme, locale },
  files: FileEntry[],        // 当前文件集（完整内容）
  plan: Plan | null,
  checks: Check[],
  version: number,
  createdBy: string,         // 访客标识（展示用，非安全边界）
  createdAt, updatedAt
}

Plan   { name, summary, stack, steps: string[], files: {path, purpose}[] }
Check  { id, label, ok, level: 'block'|'warn'|'info', detail? }
Version{ id, projectId, seq, label, prompt, files: FileEntry[], changed: string[], createdAt }
Message{ id, projectId, role: 'user'|'agent'|'system', kind: 'text'|'plan'|'error'|'notice',
         content, meta?, createdAt }
```

## 4. 生成协议 NWF

### 4.1 语法

```
<note>自由文本，作为 Agent 口播</note>
<plan>{"name":"…","summary":"…","stack":"…","steps":[…],"files":[{"path":"…","purpose":"…"}]}</plan>
<file path="index.html">
（原始内容，不转义）
</file>
<delete path="old.js"/>
```

### 4.2 状态机

```
      ┌────────┐  <plan>   ┌──────┐  </plan>  ┌────────┐
      │ OUTSIDE│──────────▶│ PLAN │──────────▶│ OUTSIDE│
      └────────┘           └──────┘           └────────┘
           │ <file path>                ▲
           ▼                            │ </file>
      ┌────────┐  任意字符（累积）        │
      │  FILE  │────────────────────────┘
      └────────┘
```

实现要点：

- 维护 `buffer`，每次 `push(chunk)` 循环匹配"下一个标签"，**只处理已完整到达的标签**，半截留在 buffer；
- `<` 开头但构不成标签的字符退化为正文（容忍模型写 `a < b`）；
- `push()` 与 `end()` **永不抛异常** —— 所有异常路径降级为 `warning` 事件；
- 逐字符喂入与整体喂入产出**完全一致**的事件序列（UT-PROTO-02/03 用随机分块断言）。

### 4.3 漂移纠正（`llm.ts` 的流处理）

| 漂移 | 纠正 |
| --- | --- |
| 用 ` ```html ` 包裹整个 `<file>` | `file_end` 时剥围栏 |
| 写成 `<file name="a.html">` | 属性名兼容 `name` / `filename` |
| 大小写 `<FILE PATH=…>` | 标签名与属性名转小写后匹配 |
| 忘记 `</file>` 直接开下一个 `<file>` | 收尾前一个并标 `truncated`，产生 warning |
| 输出正文前有元话语 | OUTSIDE 状态自动归入 note |

**纠正只发生在格式层**：不重试整轮、不改写代码内容、不猜测缺失文件。

### 4.4 路径安全

`sanitizePath()` 白名单：`[A-Za-z0-9_\-.]` 与 `/`；拒绝 `..`、绝对路径、空段、以 `.` 开头的段、超长路径。非法路径 → 丢弃该文件 + warning。

## 5. 引擎层

### 5.1 接口

```ts
interface AgentEngine {
  id: EngineId
  plan(ctx: GenContext): Promise<Plan>
  write(ctx: GenContext, plan: Plan): AsyncIterable<string>   // 原始协议文本
}
```

### 5.2 本地引擎（`composer.ts`）

一条**确定性编译管线**，不是模板替换：

```
prompt ──▶ ① 意图分类 ──▶ ② 槽位抽取 ──▶ ③ 配方选择 ──▶ ④ 代码发射 ──▶ ⑤ 协议序列化
          (加权词表)      (实体/字段/风格)   (archetype)     (HTML/CSS/JS)
```

| 阶段 | 做什么 |
| --- | --- |
| 意图分类 | 7 个 archetype（`expense` `todo` `notes` `pomodoro` `kanban` `calculator` `landing`），加权词表 + 原型先验；同分时用 prompt 哈希稳定裁决（**同输入必同输出**） |
| 槽位抽取 | `appName` / `accent` / `theme` / `fields` / `currency` / `sampleData`；显式词优先于设置偏好 |
| 配方发射 | 每个配方 = `{state, actions, render, style, a11y}` 五段发射函数，共享同一套设计令牌与布局骨架 |
| **迭代保留类型** | 迭代时若新指令**没有点名应用类型**，沿用原来的 archetype（从产物的 `nucleus:<archetype>:v1` 指纹反推）。否则「把主色换成墨绿」会把一个记账应用整个换成落地页 |
| 协议序列化 | 拼成 NWF 文本，由 `runner` 切片成 720 字符 / 55ms 的流 |

**「真编译器」的判定**（UT-COMP-10 变异测试守着）：同一句需求只改主色 → 产物色值必须变；改应用名 → 标题 / storage key / 导出文件名跟着变；改货币 → 金额格式化从 ¥ 变成 $。

### 5.3 云端引擎（`llm.ts`）

OpenAI 兼容：`POST {baseUrl}/chat/completions`，`stream: true`，逐帧解 `choices[0].delta.content`。

三件容易漏掉的事：

| 事项 | 实现 |
| --- | --- |
| SSRF 防护 | 只允许 http/https；拒绝 `localhost` / `127.` / `10.` / `172.16-31.` / `192.168.` / `169.254.` / `[::1]`（测试钩子 `NUCLEUS_ALLOW_LOCAL_LLM=1` 可临时放开） |
| 超时 | 首字节 30s；空闲 60s；两者都区分开，避免"卡住"和"慢"混为一谈 |
| 错误码归一 | 401/403 → `llm_auth`；429/402 → `llm_quota`；其余 → `llm_network`；超时 → `llm_timeout` |

单个坏帧（JSON 解析失败）被跳过，不中断整条流。

### 5.4 上下文选择策略（`prompts.ts`）

迭代轮要把当前文件回传给模型。预算 `MAX_CONTEXT_CHARS = 24000`。

**旧策略的问题**：按路径顺序累加，超预算后剩下的文件**整份消失** —— 模型会以为那个文件不存在，于是把它整个重建。

**现在的策略**：

1. **打分**：语义类别亲和度（分路径权重）+ 词法命中 + 入口文件保底分；
   ```
   指令「把主色换成墨绿」→ styles.css +8 · index.html +3
   指令「加一个筛选按钮」→ app.js +8   · index.html +3
   指令「重新排一下布局」→ index.html +8 · styles.css +2
   ```
2. **选取**：按分数降序（同分按体积升序），放得下就完整放，放不下就**截断**而不是丢弃（截断后至少给 600 字符，否则跳过）；
3. **保底**：入口文件始终有基础分，模型至少看得到页面骨架；
4. **manifest**：上下文里附一份清单，列出**全部**文件及其状态（完整 / 已截断 / 未提供内容），让模型知道项目里还有什么。

分词：英文按词，中文按**二元组**（单字噪声太大，"色"几乎每个 CSS 都命中）。

## 6. 编排层（`runner.ts`）

```ts
generate(ctx, engine, sink)
  ├─ stage(plan, running) → engine.plan() → plan 事件 → stage(plan, done)
  ├─ stage(write, running)
  │    └─ for await (chunk of engine.write())
  │         parser.push(chunk) → 逐事件转发
  ├─ parser.end() → 收尾未闭合的文件（标 truncated）
  ├─ stage(write, done)
  ├─ 若一个文件都没有 → error(protocol_error) + 附原文前 180 字
  ├─ stage(verify) → assemble(files) → check 事件 × N
  └─ done(version=0, usage)   // 这一条不转发给前端，真正的 version 由路由层提交后给出
```

`GenSink` 记录本轮产物：

```ts
interface GenSink {
  files: Map<string, string>   // 当前文件集（起始值 = 旧文件）
  completed: Set<string>       // 本轮**正常闭合**的文件路径
  deleted: Set<string>         // 本轮被删除的路径
  plan, checks, warnings, raw, usage
}
```

### 6.1 中断保留语义（新增）

用户点「停止」时，客户端**不关闭 SSE**，而是调 `POST /api/projects/:id/stop`：

```
客户端                          服务端
──────                          ──────
POST /stop ─────────────────▶   running.get(id).abort()
                                ↓
                          引擎停止 → runGeneration 收尾
                                ↓
                          aborted = signal.aborted
                                ↓
                    partialFiles(sink, previous)：
                      · completed 里的文件 → 用新内容
                      · 写了一半的文件   → 回退到旧内容
                      · 本轮新开没写完的 → 直接丢弃
                      · deleted 里的      → 保持删除
                                ↓
                    有变化 → store.commit(label: "中断保留 · N 个文件有变化")
                    无变化 → 不产生版本（避免历史里全是空版本）
                                ↓
◀────────────────────────────  done(version, partial: true)
```

这样设计的好处：**客户端能收到确认**（不必靠轮询版本号），而且数据不会因为"手快关掉页面"而丢失 —— 客户端断开时服务端同样会提交已完成的部分。

## 7. 预览组装与沙箱（`preview/assemble.ts`）

### 7.1 组装算法

输入 `FileEntry[]`，输出 `{html, entry, checks, inlined, missing}`：

1. 选入口：`index.html` → `index|main|app*.html` → 第一个 `.html`；
2. 内联 CSS：`<link rel="stylesheet" href="styles.css">` → `<style data-src="styles.css">…</style>`（**保持原位置**，保证层叠顺序）；
3. 内联 JS：`<script src="app.js"></script>` → `<script data-src="app.js">…</script>`（保持原位置，保证执行顺序）；
4. 注入错误桥 + storage shim（插在 `<head>` 之后、业务脚本之前 —— 否则解析阶段的错误会漏捕获）；
5. 若有设计微调，在 `</head>` 前注入 `<style data-nucleus="tweak">`（同优先级后写者胜，无需 `!important`）；
6. 产出 7 项静态检查。

### 7.2 静态检查项

| id | 标签 | 级别 | 判定 |
| --- | --- | --- | --- |
| `entry` | 入口文件存在 | block | 存在入口 HTML |
| `refs` | 引用完整性 | warn | 所有相对引用都存在 |
| `structure` | HTML 结构完整 | warn | 含 `<html>` 与 `<body>` |
| `size` | 体积在预算内 | warn | 总字节 ≤ 400KB |
| `external` | 外部依赖检查 | info | 列出 CDN 外链（离线不可用） |
| `sandbox_safe` | 沙箱越权检查 | warn | 不含 `parent.document` / `top.location` 等 |
| `theme_vars` | 可用设计令牌 | info | 声明了 `--accent` / `--radius`，微调面板可生效 |

`block` 级失败会挡住预览；`warn` / `info` 只提示。结果同时出现在：对话流的检查徽章 + 预览工具栏的**常驻健康度指示灯**（点开看明细）。

### 7.3 错误桥

注入到每个预览文档最前面：

```js
addEventListener('error', ...)            // 资源加载失败 + 脚本错误
addEventListener('unhandledrejection', ...)
console.error = 包装                      // 把 console.error 也当错误
post({ kind: 'ready' })                   // 预览就绪
```

父窗口只信任 `event.source === iframe.contentWindow` 且带 `__nucleus: 1` 标记的消息。

### 7.4 storage shim 与回灌

沙箱是**不透明源**（没有 `allow-same-origin`），原生 `localStorage` 会抛 `SecurityError`：

```
生成的应用  →  shim.setItem()  →  postMessage({kind:'storage', op:'set'})
                                            ↓
宿主（src/lib/seed.ts） → 写进浏览器 localStorage（键：nucleus.seed.<projectId>）
                                            ↓
重新挂载预览 → injectSeed() 把种子写进 <head> 之后的 window.__NUCLEUS_SEED
                                            ↓
                              沙箱内 shim 初始化时读种子 → "刷新数据还在"
```

代价：生成的应用读不到宿主的任何数据；收益：不把宿主源暴露给不可信代码。

## 8. 持久化与版本（`store/store.ts`）

### 8.1 原子写

```ts
const tmp = `${file}.${process.pid}.tmp`
await fs.writeFile(tmp, JSON.stringify(db), 'utf8')
await fs.rename(tmp, file)          // 同分区 rename 是原子的
```

- 单进程内用**串行写队列**（`this.queue = this.queue.then(doSave)`）防并发撕裂；
- 文件损坏时自动改名备份为 `db.json.corrupt.<ts>` 并重建，避免整个应用起不来；
- 首次启动写入种子数据。

### 8.2 版本模型

- `generate` / `rollback` 成功后落一份**完整文件快照** + `changed[]`（与上一版比对得出的路径集合，含被删除的路径）；
- `rollback(seq)`：把目标版本复制成**新版本**（label `回滚至 vN`），历史不删；
- 裁剪：单项目版本超过 30 时，保留首版 + 最近 5 版。

**为什么用快照而不是 diff**：一个应用 20–60KB，快照成本可忽略，换来回滚 O(1) 且永不出现"diff 链断裂导致无法还原"。

### 8.3 一致性

生成过程中的文件**不落盘**，只有提交时才一次性写入（files + version + messages + usage）。因此"用户中途停止"= 不产生脏版本。

### 8.4 容量与裁剪

| 对象 | 上限 | 策略 |
| --- | --- | --- |
| 消息 | 每项目 80 条 | 超出后丢最旧的 |
| 版本 | 每项目 30 个 | 保留首版 + 最近 5 版 |
| 单文件 | 200KB | `MAX_FILE_BYTES` |
| 单项目总量 | 400KB | `MAX_TOTAL_BYTES` |
| 需求描述 | 2000 字 | `PROMPT_MAX_LENGTH` |

## 9. HTTP 接口

### 9.1 路由表

| 方法 | 路径 | 说明 | 成功 | 失败 |
| --- | --- | --- | --- | --- |
| `GET` | `/api/health` | 健康检查 | 200 `{ok, engine, seeded, uptime, version}` | — |
| `GET` | `/api/projects` | 项目列表（按 `updatedAt` 倒序） | 200 `{projects}` | — |
| `GET` | `/api/projects?mine=1` | 只返回当前访客的项目（按 `x-visitor` 头过滤） | 200 `{projects}` | — |
| `POST` | `/api/projects` | 建项目（**不阻塞生成**） | 201 `{project, previewHtml, checks}` | 400 |
| `GET` | `/api/projects/:id` | 详情：项目 + 消息 + 版本 + 预览 HTML | 200 | 404 |
| `PATCH` | `/api/projects/:id` | 重命名 / 保存设计微调（`{name?, tweak?}`，`tweak:null` 清除） | 200 `{project, previewHtml}` | 404 |
| `DELETE` | `/api/projects/:id` | 删除项目及其版本/消息 | 200 `{ok}` | 404 |
| `POST` | `/api/projects/:id/generate` | **SSE 生成 / 迭代** | 200 `text/event-stream` | 400 / 404 / 409 / 412 / 502 |
| `POST` | `/api/projects/:id/stop` | **停止当前生成**（连接不关，服务端提交已完成部分） | 200 `{ok}` | 409 |
| `POST` | `/api/projects/:id/rollback` | 回滚到指定版本（生成新版本） | 200 `{project, version}` | 400 / 404 |
| `GET` | `/api/projects/:id/export` | 下载 ZIP | 200 `application/zip` | 400 / 404 |
| `GET` | `/api/share/:slug` | 分享页数据 | 200 `{project, html, checks}` | 404 |
| `GET` | `/p/:slug` | 302 → `/#/p/:slug`（方便粘贴裸链接） | 302 | — |
| `GET` | `/api/settings` | 读取设置（Key 只出掩码） | 200 | — |
| `PUT` | `/api/settings` | 写入设置 | 200 | 400 / 405 |
| `POST` | `/api/settings/test` | 连通性测试 | 200 `{ok, ms, sample, model}` | 412 / 502 |

静态资源走 `serveStatic`，SPA 回退到 `index.html`；路径经 `normalize` + 前缀校验，防目录穿越。

### 9.2 SSE 帧格式

```
data: {"type":"stage","stage":"plan","status":"running"}

data: {"type":"plan","plan":{"name":"随手记账", …}}

data: {"type":"file_start","path":"index.html"}

data: {"type":"file_delta","path":"index.html","chunk":"<!DOCTYPE html>…"}

data: {"type":"file_end","path":"index.html","lines":128,"content":"…"}

data: {"type":"check","check":{"id":"entry","ok":true,"label":"入口文件存在"}}

data: {"type":"done","version":2,"usage":{"ms":812,"engine":"local","chars":20480}}

data: {"type":"error","code":"llm_auth","message":"模型拒绝请求（401）：invalid api key"}
```

### 9.3 错误码

| code | HTTP | 含义 | 前端动作 |
| --- | --- | --- | --- |
| `bad_request` | 400 | 参数非法（空 prompt、超长、非法 JSON） | 就地提示 |
| `not_found` | 404 | 项目/版本/分享链接不存在 | 回首页 |
| `busy` | 409 | 该项目已有生成进行中 | 等待或停止 |
| `engine_unconfigured` | 412 | 选云模型但未配置 Key | 去设置 |
| `llm_auth` | 502 | Key 无效/无权限 | 去设置 |
| `llm_quota` | 502 | 额度或限流 | 重试 |
| `llm_timeout` | 502 | 首字节/空闲超时 | 重试 |
| `llm_network` | 502 | 连不上上游 | 去设置 |
| `protocol_error` | 502 | 模型没按协议输出任何文件 | 重试 |
| `internal` | 500 | 兜底 | 重试 |

前端的映射表在 `src/lib/errors.ts`：每个错误码 → **标题 + 原因 + 一个可点按钮**（去设置 / 重新生成 / 回首页）。

## 10. 前端

### 10.1 路由

自研 hash 路由（`src/App.tsx`），约 40 行：

```
#/            首页
#/studio/:id  工作台
#/p/:slug     分享页
#/settings    设置
```

hash 路由的好处：静态托管零配置，刷新不 404，不需要服务端配合。

### 10.2 状态管理

工作台用**单个 `useReducer` 风格的 `applyEvents` 归约**：

```ts
live: {
  running, stage, plan,
  files: {path, content, lines, done}[],
  checks: Check[], warnings: string[], note: string
}
```

| 规则 | 原因 |
| --- | --- |
| `live.files` 与 `project.files` 分离 | 流式期间显示 live，`done` 后以**服务端返回的项目为准**（服务端是唯一真相） |
| 打字机节流 | `file_delta` 先入队，`requestAnimationFrame` 批量 flush，避免每个 chunk 一次 setState |
| 中止 | `AbortController` → 关闭 SSE → 丢弃 `live`，保留旧项目状态 |
| 项目列表缓存 | 30s TTL，`force` 参数可绕过（首页「刷新」按钮） |

### 10.3 SSE 消费（`src/lib/api.ts`）

逐块 `reader.read()` → 累积 buffer → 按 `\n\n` 切帧 → 逐行取 `data:` 前缀 → `JSON.parse`。**坏帧跳过，不打断整条流**。

### 10.4 样式系统

无 UI 库、无 Tailwind。手写 CSS（`src/styles.css`），用 CSS 变量做设计令牌：

```css
--ink / --ink-soft / --muted / --line / --bg-soft / --accent / --danger / --radius / --mono
```

所有交互元素可 Tab 聚焦，对比度 ≥ 4.5:1，支持 `prefers-reduced-motion`。

## 11. 安全模型

| 面 | 威胁 | 对策 |
| --- | --- | --- |
| 生成代码执行 | 读取宿主 DOM / cookie / 接口 | `iframe sandbox` **不含** `allow-same-origin` → 不透明源 |
| 生成物持久化 | 沙箱内 storage 不可用 | 内存 shim + 宿主回灌（§7.4），数据不出浏览器 |
| 路径穿越 | `../etc/passwd` 写入/导出 | `sanitizePath` 白名单；导出时二次校验 |
| XSS（平台自身） | 模型输出或用户输入注入 | 不使用 `dangerouslySetInnerHTML` 渲染原始文本；高亮**先切词再 escape**（顺序反了就是漏洞） |
| API Key 泄露 | Key 出现在前端或日志 | 只存服务端；接口只回显 `sk-****abcd`；不写日志 |
| SSRF | 用 Base URL 探测内网 | 只允许公网 http(s)，拒绝内网网段 |
| 提示词注入 | 用户输入里写 `</file>` 撑破上下文 | `sanitizeUserPrompt` 把定界符转义为全角 |
| 并发竞态 | 同一项目两次生成互相覆盖 | `running` Map 做项目级互斥，第二个请求 409 |
| 写响应后连接已关闭 | 客户端断开后服务端继续 `res.write` → `ERR_STREAM_DESTROYED` 崩溃 | `send()` 检查 `clientGone / writableEnded / destroyed`；`res.on('error')` 吞掉写错误 |
| 数据隔离 | 无账号体系 | **明确的取舍**：项目公开可读可写，`createdBy` 仅 UI 标记，不是安全边界（文档与界面均已明示） |

## 13. 部署与运维

### 13.1 命令

```bash
npm install
npm run build      # tsc --noEmit && vite build && esbuild server → dist/server.js
npm start          # prestart 自动 build → node dist/server.js
npm run dev        # Vite HMR（前端热更新，服务端另跑 npm run dev:api）
npm test           # Vitest：单元 + 集成（132 条）
npm run e2e        # Playwright：真实 Chrome 10 步（需先 npm start）
```

### 13.2 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 监听端口，绑定 `0.0.0.0` |
| `NUCLEUS_DATA_DIR` | `data` | 数据目录（内含 `db.json`） |
| `NUCLEUS_CLIENT_DIR` | `dist/client` | 前端产物目录 |
| `NUCLEUS_LLM_KEY` | 空 | 云端引擎 Key（也可在设置页填） |
| `NUCLEUS_LLM_BASE_URL` | 空 | 云端引擎地址 |
| `NUCLEUS_LLM_MODEL` | 空 | 云端引擎模型名 |
| `NUCLEUS_ALLOW_LOCAL_LLM` | `0` | 测试钩子：允许把上游指向 127.0.0.1 |

### 13.3 数据与备份

- 全部状态在 `data/db.json` 一个文件里 → **备份 = 复制这个文件**；**重置 = 删掉它**（下次启动会重建并写入 3 个种子项目）；
- 容器重建会丢 `data/`，因此内置种子项目兜底，首页永远不会白屏；
- 生成的应用里的数据在**访客浏览器**里，不在服务端。

### 13.4 排障手册

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 打开页面提示「前端产物未构建」 | `dist/client` 不存在 | 跑 `npm run build` |
| 首页空白、无项目 | `data/db.json` 损坏 | 看是否有 `db.json.corrupt.<ts>` 备份；删掉 `db.json` 重启 |
| 生成一直转圈 | 上游连不上 | 设置页「测试连接」；检查地址与网络 |
| 点「停止」没反应 | 生成已结束 | 正常；按钮只在生成中可见 |
| 预览打不开 | 缺入口文件 | 预览区会显示具体原因；对话里说「补一个 index.html」 |
| 应用里数据刷新就没了 | 浏览器清了 localStorage 或换设备 | 种子只存在当前浏览器；换设备属预期 |
| `/api/...` 返回 409 | 同项目已有生成在进行 | 等它结束或点「停止」 |
| 设置页保存失败 400 | Base URL 指向内网 | 换公网地址 |

### 13.5 部署形态

单进程 + 本地磁盘：容器内 `npm install && npm start`，暴露 `PORT`。静态资源与 API 同源，无 CORS、无预检。多实例部署需要换成外部数据库（`Store` 接口已预留，见 §15）。

## 15. 扩展指南

三处接缝（详见 [03 §7](03-技术架构文档.md)）：

### 15.1 换生成引擎

```ts
// server/agent/runner.ts
export interface AgentEngine {
  id: EngineId
  plan(ctx: GenContext): Promise<Plan>
  write(ctx: GenContext, plan: Plan): AsyncIterable<string>
}
```

实现这个接口 → 在 `createEngine()` 里注册 → 上层零改动。输出必须是 NWF 协议文本。

### 15.2 换成真沙箱（E2B / WebContainer）

只需替换两处：

1. `server/preview/assemble.ts` 的 `assemble()`：把文件写进沙箱、取回预览 URL；
2. `src/components/PreviewPanel.tsx` 的渲染分支：`srcdoc` → `src`。

事件模型、`AgentEvent`、对话流、版本逻辑**都不用动** —— 这就是接缝存在的意义。

### 15.3 换持久化

实现 `Store` 的 8 个方法（`listProjects` / `getProject` / `getBySlug` / `createProject` / `updateProject` / `deleteProject` / `listMessages` / `appendMessage` / `listVersions` / `getVersion` / `commit` / `rollback` / `getSettings` / `updateSettings` / `detail`），把 `FileStore` 换成 `PostgresStore` 即可。注意保留两个语义：

- `commit()` 必须**整份快照**（回滚依赖它）；
- `listProjects(mine?)` 是展示层过滤，不是安全边界。

### 15.4 加一个静态检查项

在 `assemble()` 的 `checks.push(...)` 加一项 → 前端自动显示（对话流徽章 + 健康度指示灯）。

### 15.5 加一个页面

`src/App.tsx` 的路由表加一条 → 新建 `src/pages/Xxx.tsx` → 需要数据就往 `src/lib/api.ts` 加一个方法 + 服务端加一条路由。

## 16. 已知限制

| 限制 | 根因 | 解除条件 |
| --- | --- | --- |
| 单进程存储 | 本地文件 + 串行写队列 | 换 Postgres（§15.3） |
| 不支持构建型产物 | 纯前端沙箱没有构建步骤 | 执行层换真沙箱（§15.2） |
| 上下文预算 24000 字符 | 迭代轮全量回传文件 | 已做相关度排序 + 截断；再进一步需引入检索式上下文 |
| 无身份体系 | 题面要求免注册 | 需要账号体系时再加（`createdBy` 已留字段） |
| 沙箱无同源 | 安全要求 | 重新设计隔离模型 |
| 单阶段输出，无角色分工 | 一次模型调用产出 plan+files | 提示词 + 事件分层改造（[04 §2.4](04-技术设计文档.md)） |
| 7 类原型的覆盖 | 本地引擎的配方数量 | 加 archetype，或切云模型 |
| 只跑 Chrome 的 E2E | 自动化环境限制 | 补 Safari/Firefox |
| 本地引擎只认「槽位」 | 它是确定性编译器，不理解任意功能描述 | 开放域需求切云模型 |
